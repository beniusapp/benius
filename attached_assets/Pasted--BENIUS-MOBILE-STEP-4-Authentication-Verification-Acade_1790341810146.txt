# BENIUS MOBILE — STEP 4

## Authentication Verification + Academic Session Foundation + Exact Web UI Fidelity

We are continuing development of the native BENIUS mobile application.

IMPORTANT: This is STEP 4 ONLY.

Do not start implementing Student, Teacher, Admin, Attendance, Examination, Timetable, Fees, Reports, Dashboard, or other full application modules yet.

# 3. PERMANENT MULTI-TENANT REQUIREMENT

BENIUS is a multi-tenant / multi-school application.

This requirement is permanent.

Every mobile operation must remain strictly scoped to the authenticated school/tenant.

Never allow:

* Cross-school student access
* Cross-school teacher access
* Cross-school admin access
* Cross-school attendance
* Cross-school examination data
* Cross-school timetable data
* Cross-school fee data
* Cross-school academic sessions
* Cross-school reports
* Cross-school calculations
* Cross-school configuration

Never trust a school ID supplied by the mobile client when the server can derive the authenticated school from the authenticated mobile principal.

The server remains the source of truth.

# 4. PERMANENT ACADEMIC SESSION REQUIREMENT

Academic Session is NOT authentication identity.

Authentication identifies the:

* User
* Role
* School/Tenant

Academic Session identifies the academic context in which the user is operating.

The selected Academic Session must therefore remain separate from authentication.

Future session-sensitive operations must explicitly use:

Authenticated School/Tenant
+
Authenticated Principal
+
Selected Academic Session ID

Do not merge these concepts.

# 12. SESSION SWITCHING

When the user changes Academic Session:

1. Update the selected Academic Session ID.
2. Validate it against the authenticated user's authorized sessions.
3. Persist the selection.
4. Update the API session context/header.
5. Invalidate/refetch session-sensitive queries.
6. Prevent stale data from the previous session being displayed as if it belonged to the newly selected session.

Do not reload the entire application unnecessarily if TanStack Query can safely handle invalidation/refetching.
