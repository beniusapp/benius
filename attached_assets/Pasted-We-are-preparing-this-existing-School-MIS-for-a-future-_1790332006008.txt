BLOCKER 2 — EXAM CONTROLLER ACADEMIC SESSION ISOLATION
======================================================

This is a NON-NEGOTIABLE requirement for this MIS.

The entire Admin → Exam Controller module must be explicitly scoped to:

```
authenticated school/tenant
+
selected Academic Session ID
```

Every Exam Controller operation must respect both boundaries.

This includes:

* reading aggregated examination data
* reading promotion outcomes
* promotion overrides
* creating overrides
* updating overrides
* deleting overrides
* bulk deleting overrides
* executing promotion
* promotion decision ledger
* history linkage
* cleanup operations
* any related Exam Controller state

Previously identified issue:

Promotion overrides are currently school-scoped but do not contain/consistently enforce Academic Session ID.

The aggregated Exam Controller read can therefore combine session-filtered examination data with overrides that are not Session-filtered.

This must be corrected.

==================================================
SESSION OWNERSHIP
=================

The server must NOT trust an arbitrary Academic Session ID supplied by the mobile/web client.

When an Academic Session ID is supplied:

1. Resolve it through the authenticated school/tenant.

2. Verify that the Session belongs to the authenticated school.

3. Reject a Session belonging to another school.

4. Do not silently switch to another school's Session.

5. For Exam Controller operations, require an explicit selected Academic Session where the operation is Session-owned.

6. Do not accidentally fall back to another Session for an Exam Controller operation.

7. A new Academic Session must start with a fresh Exam Controller operational context.

8. Previous Session overrides must never appear in the new Session.

9. Historical/archived Session data must remain available only within its own Session context.
