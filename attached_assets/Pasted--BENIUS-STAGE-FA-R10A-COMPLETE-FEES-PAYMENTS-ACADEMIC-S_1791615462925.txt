# BENIUS — STAGE FA-R10A
## COMPLETE FEES & PAYMENTS ACADEMIC SESSION VS GLOBAL DATA CLASSIFICATION AUDIT

### STRICT READ-ONLY — NO CODE OR DATABASE CHANGES

BENIUS is a multi-tenant School Management Information System.

The owner wants to understand which features inside Principal Portal → Fees & Payments are:

1. Academic Session based.
2. Global across Academic Sessions within the same school.
3. Hybrid — containing both session-specific and school-global data.
4. Unclear or incorrectly scoped.

The six visible tabs are:

- Financial Analytics
- Fee Structures
- Ledger & Transactions
- Reminders
- External Portal
- Audit Log

Inspect the actual application implementation. Do not assume a whole tab has one classification.

## 1. Discover every feature

For EACH of the six tabs, identify all submodules, tables, forms, settings, actions, filters, PDF exports, and underlying records.

Inspect frontend, backend routes, services, and database schema definitions.

Also inspect hidden/conditional features and supporting workflows used by each tab.

## 2. Classify every feature

Use these classifications:

**SESSION-SCOPED**

Data is owned by a specific Academic Session and must not be mixed with another session.

**SCHOOL-GLOBAL**

Data is shared across Academic Sessions but must remain isolated to the authenticated school.

**HYBRID**

A feature uses school-global configuration alongside Academic Session-specific operational records.

**UNVERIFIED / RISK**

Session ownership is absent, ambiguous, inconsistently enforced, or not proven.

For every feature explain:

- What data it reads.
- What data it writes, if applicable.
- Whether the database table has `school_id`.
- Whether it has `session_id`.
- Whether session ownership is established through a related invoice or another record.
- Whether the selected Academic Session affects the result.
- Whether the data persists unchanged when the selected session changes.
- Whether active/archived session behavior differs.
- Whether current student enrollment can affect historical displays.
- Whether exports and PDFs follow the same scoping.
- Whether the authenticated school is always enforced.

A table without `session_id` is NOT automatically global if session ownership is derived through a related record.

Likewise, a UI session filter alone is NOT proof of database session isolation.
