We have completed Attendance Step 2E.

Current canonical Attendance identity is now:

    school_id + session_id + student_id + date

And:

- attendance_records.session_id is NOT NULL
- unique (school_id, session_id, student_id, date) exists
- Attendance Session FK no longer SET NULL
- Teacher POST /api/attendance gets the active Session server-side
- Student Registry remains GLOBAL and session-independent
- Enrollment is NOT an Attendance prerequisite
- Faculty Mapping is NOT an Attendance restriction
- Any authenticated Teacher belonging to the school may mark Attendance
- Attendance must remain strictly tenant-specific
- Attendance must remain Academic-Session-specific

The next task is to audit READ-SIDE Session isolation only.

==================================================
GOAL
==================================================

Determine whether every Attendance reader in Admin, Teacher, and Student portals correctly reads ONLY the selected Academic Session.

For every Attendance read, identify:

1. Which school/tenant is being used.
2. Which Academic Session is being used.
3. Whether session_id is explicitly included in the database query.
4. Whether the selected Session comes from authenticated/server-authoritative context or browser input.
5. Whether current Student Registry data is incorrectly being used to reconstruct historical Attendance.
6. Whether date-only queries can mix Sessions.
7. Whether calculations/aggregations can mix Sessions.
8. Whether a selected previous Session can display historical Attendance correctly.
9. Whether current Session data can leak into a previous Session view.
10. Whether previous Session data can leak into the current Session view.

Do NOT fix anything.
