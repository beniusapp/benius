OBJECTIVE:

PART 1 — SEPARATE TWO NOTIFICATION TYPES

A. UNREAD RED DOT

- Indicates new actionable items that the Admin has not yet viewed.
- Appears on the relevant submodule and its parent module.
- Disappears when the Admin opens the corresponding submodule and the current items have been successfully loaded and displayed.
- Opening one submodule must not clear another submodule's unread red dot.
- A parent red dot disappears only when all its relevant child notifications have been viewed.
- A newly arriving item must produce a new unread indicator after data refresh.
- A failed or still-loading request must never mark items as seen.

B. PENDING-ACTION NUMERIC COUNT

- Represents unresolved work.
- Must remain visible after the Admin opens a module.
- Decreases only when the underlying item is approved, rejected, resolved, removed, or otherwise leaves the applicable pending state.
- Must remain the source of truth for Action Required.

Do not combine unread counts with pending counts.

PART 6 — MINIMAL SEEN/UNSEEN STORAGE

Implement the smallest safe browser-local seen-state mechanism without database changes.

Requirements:

- Scope by authenticated Admin identity.
- Scope by School ID.
- Scope by Academic Session ID for session-owned notification sources.
- Keep Gallery and E-Book seen state school-wide.
- Scope independently by submodule.
- Use stable underlying record IDs, not just counts.
- Do not mix notification state between Admin accounts or schools.
- Handle missing or malformed browser storage safely.
- Do not store complaint messages, leave details, student names, or other sensitive record content in browser storage.
- Never mark a record seen merely because the parent dashboard was opened.
- Mark only successfully loaded and actually displayed items as seen.
- Do not mark records from an unrelated hidden tab as seen.
- Avoid unbounded growth of stored seen IDs; prune safely without making existing pending items repeatedly appear unread.
- Treat the initial state as unread for existing actionable items unless an existing reliable seen-state mechanism dictates otherwise.

Browser-local seen state does not need to synchronize across devices.

Do not create new database tables, columns, APIs, or server-side read markers.
