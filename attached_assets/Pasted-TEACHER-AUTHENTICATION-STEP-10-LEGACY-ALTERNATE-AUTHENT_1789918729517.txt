==================================================
SECURITY ARCHITECTURE THAT MUST REMAIN AUTHORITATIVE
==================================================

The accepted Teacher Forgot Password architecture is:

Teacher Login
→ School Code + Registered Teacher Email
→ tenant-safe Teacher lookup
→ server-side recovery challenge
→ OTP
→ server-side recovery session
→ password-reset state
→ server-side reset token
→ atomic password reset
→ session revocation
→ Teacher Login

The browser must never be authoritative for:

- schoolId
- tenantId
- userId
- teacherId
- challengeId
- resetToken

The secure recovery endpoints are:

POST /api/teacher/forgot-password

POST /api/teacher/verify-otp

POST /api/teacher/reset-password

==================================================
MULTI-TENANT SECURITY REQUIREMENT
==================================================

This is a TRUE MULTI-TENANT SaaS application.

School/tenant isolation is permanent and non-negotiable.

A Teacher belonging to School A must never be able to:

- authenticate as School B
- reset a School B Teacher password
- use a School B recovery challenge
- use a School B reset token
- access another school's Teacher authentication state
- bypass tenant checks through a legacy endpoint

Any alternate authentication path must preserve:

authenticated school / tenant boundary

and must not introduce a global Teacher identity lookup.

SEVERITY CLASSIFICATION
==================================================

Use only these classifications:

CRITICAL:
A reachable authentication/password-reset path allows cross-tenant access, unauthorized password reset, authentication bypass, or exposure of a reset credential.

HIGH:
A reachable authentication/recovery path significantly weakens tenant isolation or credential security but does not demonstrate direct account takeover.

MEDIUM:
A reachable security weakness with meaningful but limited impact.

LOW:
A non-exploitable hardening issue or inactive/legacy concern.

INFORMATIONAL:
Unused/unreachable legacy code or documented compatibility code with no active security impact.

Do not invent severity.
