We have identified a bug in the Teacher Dashboard → Examination → Add Marks flow.

IMPORTANT:
Before making any changes, inspect the existing implementation and explain exactly what you will change. Do not modify unrelated modules, database schema, enrollment rules, attendance behavior, grading calculations, promotion logic, or existing data.

ROOT CAUSE:

The Examination Add Marks page currently gets its student roster from:

GET /api/attendance/:schoolId/:class/:section/:date

For the active/current-session view, that endpoint uses the broad student query:

getStudentsByClassSection()

which filters students by:

school_id
class
section
is_active

It does NOT require the student to have an enrollment in the currently active academic session.

However, POST /api/exam-scores correctly validates every submitted student against the selected academic session:

schoolId
sessionId
studentId
class
section

Therefore Examination can display students who the Save Scores API correctly rejects with:

"Every student must belong to this class-section in the selected session."

CURRENT EXAMPLE:

School: 1
Class: 6
Section: A
Subject: Physics

Active session:
2028-2029
Session ID: 30375

The Examination roster currently displays students 4 and 7 because their students.class and students.section are 6/A.

But neither student has an enrollment matching session 30375 + class 6 + section A.

Student 4:
- No enrollment record.

Student 7:
- Enrollment exists for session 41, class 6/A.
- No enrollment exists for active session 30375.

Teacher authorization is valid:
Teacher ID 6
Class 6
Section A
Subject Physics

DO NOT weaken or remove the existing enrollment validation in POST /api/exam-scores.

REQUIRED FIX:

Make the Examination Add Marks roster session-aware.

For the Examination marks-entry screen:

1. Determine the exact session being viewed:
   - If an archived/view session is explicitly selected, use that session.
   - Otherwise resolve the school's active academic session using the same session-resolution logic already used by Save Scores.

2. Retrieve students using enrollment for that exact session, class, and section.

The roster must effectively represent:

school
+ selected academic session
+ class
+ section
+ valid student enrollment

3. Only students who are legally eligible to submit scores should appear in the Examination Add Marks roster.

4. Keep POST /api/exam-scores enrollment validation unchanged as defense in depth.

5. Do NOT automatically create enrollments when saving marks.

6. Do NOT modify Attendance behavior globally unless absolutely necessary.

SAFEST ARCHITECTURE:

Prefer creating a dedicated Examination roster endpoint, for example:

GET /api/examination/roster/:schoolId/:class/:section

or another appropriately named endpoint following the project's existing API conventions.

The endpoint should:

- Resolve/use the exact requested academic session.
- Validate teacher authorization.
- Query students through the enrollment table for that session.
- Return only students enrolled in that class-section for that session.
- Preserve tenant isolation.

Then change:

client/src/pages/teacher-modules/examination.tsx

so Add Marks uses this Examination-specific session-aware roster instead of relying on the general Attendance roster.

IMPORTANT SESSION RULE:

Do not assume the student's current students.class/students.section represents their class for every academic session.

For Examination, the academic-session enrollment is authoritative.

EXPECTED BEHAVIOR:

Class 6 / A should display only students enrolled in:

session 2028-2029
class 6
