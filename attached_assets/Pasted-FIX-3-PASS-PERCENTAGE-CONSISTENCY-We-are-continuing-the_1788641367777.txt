FIX 3 — PASS PERCENTAGE CONSISTENCY

We are continuing the School MIS Examination calculation stabilization work.

IMPORTANT PERMANENT ARCHITECTURE RULE:
This is a TRUE MULTI-TENANT School MIS.

Tenant isolation is mandatory in every change.

A teacher/user from School A must never access, retrieve, calculate with, save, update, or infer School B's students, examination scores, academic sessions, policies, grading rules, results, attendance, faculty data, or other school-owned data.

The authenticated teacher's school context is authoritative.

NEVER trust a client-supplied schoolId as authorization.

==================================================
FIX 3 GOAL
==================================================

Fix PASS PERCENTAGE inconsistency.

The application currently has competing pass thresholds/logic, including historically identified values such as:

- 33%
- 35%
- passMarks
- configured Examination policy passPercentage
- hardcoded/fallback thresholds in different screens

This can cause the same student's result to be Pass in one place and Fail in another.

We need ONE AUTHORITATIVE PASS PERCENTAGE for Examination calculations.

The school's configured Examination policy passPercentage must be authoritative.

Do NOT impose a universal 33%, 35%, or any other percentage.

==================================================
REQUIRED AUTHORITY FLOW
==================================================

The intended authority chain is:

authenticated teacher
→ authenticated teacher.schoolId
→ Examination policy belonging to that school
→ configured passPercentage
→ shared Examination calculation engine
→ subject pass/fail
→ downstream Examination results

A client-supplied schoolId MUST NOT select the policy.

A teacher must never be able to calculate using another school's policy.

Preserve strict tenant isolation.

CORE REQUIREMENT
==================================================

There must be one authoritative pass percentage for Examination calculation.

The shared Examination calculation engine should receive the authoritative configured pass percentage as calculation input.

Subject pass/fail must use:

percentage >= configured passPercentage

Do not introduce another fallback threshold inside the engine.

Do not make 33 or 35 a hidden default inside the calculation engine.

Do not let passMarks silently override the configured Examination policy unless the current application architecture explicitly defines passMarks as the authoritative policy value.

If passMarks is only historical/storage/display data, do not treat it as a competing calculation authority.

Do not rewrite historical database data merely to make this fix work.

==================================================
MULTI-TENANT POLICY RESOLUTION
==================================================

When resolving the pass percentage:

1. Obtain the authenticated teacher identity.
2. Resolve the teacher's authoritative schoolId from the authenticated server-side teacher record.
3. Resolve the Examination policy for that school.
4. Verify the policy belongs to the authenticated teacher's school.
5. Use that policy's configured passPercentage.
6. Pass that value into the shared calculation engine.

Never do:

client schoolId
→ policy lookup
→ calculation

Never allow:

client schoolId
→ another school's policy

If a policy belongs to another school, reject it rather than using it.

Do not leak the existence or details of another school's policy.
