## 5. HISTORICAL PLACEMENT RESOLUTION

For each fee record, use:

- Authenticated School ID.
- Fee record Student ID.
- Fee record Academic Session ID.

Resolve the matching historical enrollment.

The required matching key is:

`schoolId + studentId + sessionId`

Requirements:

- Use the fee record's own Session ID.
- Keep existing authenticated school isolation.
- Keep existing Academic Session filtering.
- Never use current Registry class/section as historical placement.
- Never use an enrollment belonging to another Student.
- Never use an enrollment belonging to another school.
- Never use an enrollment from another Academic Session.
- Do not create or modify enrollment records.
- Do not backfill historical enrollment.
- Do not modify Registry synchronization.
- Do not change Student Profile behavior.

For bulk lists, use an efficient school/student/session-scoped query or a safe existing bulk helper.

Avoid one enrollment query per fee row.

Do not introduce duplicate fee rows through joins.

Preserve the existing invoice and payment record selection.
