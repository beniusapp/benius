# STEP 2L-3 — ATTENDANCE MODULE

## STUDENT ATTENDANCE — MARKED SUNDAY DISPLAY & MONTHLY COUNT CONSISTENCY

### CONTROLLED AUDIT + IMPLEMENTATION

We have completed and accepted:

* Step 2L-1 — server-authoritative Academic Session selection for Teacher Attendance writes.
* Step 2L-2 — Academic Session date-boundary enforcement for Teacher Student-Attendance writes.

Now address ONLY the following remaining Attendance issue identified by the Step 2L-6C audit:

> A deliberately marked Sunday is accepted and counted by the server/database, but the Student Attendance UI does not consistently display the stored Sunday status or include it correctly in the monthly UI tally.

This step must make the Student Attendance UI consistent with the authoritative Attendance record and server-side calculation.

---

# 1. HARD REQUIREMENTS — DO NOT CHANGE

## Multi-tenant isolation

* `req.session.schoolId` remains authoritative.
* Never trust browser-provided school IDs for ownership.
* Never allow cross-school Attendance access.

## Student Registry

Student Registry remains GLOBAL/PERMANENT.

Do NOT:

* recreate Students per Academic Session;
* reset Students when Session changes;
* make Enrollment a prerequisite merely for displaying historical Attendance.

## Academic Session

Student Attendance must remain Academic Session-specific.

When a Student selects an Academic Session, the UI must display Attendance belonging to that Session only.

Do not mix records from another Session.

## Sunday rule

This is extremely important:

### A Sunday is NOT automatically a working day.

If there is NO Attendance record for Sunday:

* do not invent an Attendance status;
* do not count the Sunday as Present/Absent/Late/Half Day;
* do not make the Sunday appear as a marked working day.

If there IS a deliberately stored Attendance record for Sunday:

* display the actual stored Attendance status;
* include it in the appropriate Attendance calculation/tally exactly as the server interprets it.

The existence of an Attendance record is what matters.

## Authoritative Attendance source

Student Attendance must continue using the same authoritative Attendance data as Admin/Teacher Attendance.

Do not create a second Attendance source.

Do not calculate a different Sunday status in the frontend.

## IST

Attendance business dates remain IST / Asia/Kolkata.

Do not introduce UTC date conversion for Sunday/date matching.

## Existing Attendance rules

Do not change:

* 7-day correction window;
* archived Session protection;
* Academic Session date boundaries;
* holiday rules;
* Teacher Attendance authorization;
* server-authoritative Session resolution;
* Student Registry behavior;
* Enrollment rules;
* tenant isolation.

# 2. CURRENT ISSUE TO FIX

The Step 2L-6C audit found:

* The monthly Student Attendance API returns the Sunday Attendance record/status.
* The Student Attendance calendar can identify Sunday but displays `"Sunday"` instead of the actual Attendance status.
* The monthly Student Attendance UI tally skips Sunday records.
* The stored Sunday status can therefore be visible only indirectly, such as through a tooltip, while the main calendar/tally is inconsistent.

Fix this inconsistency.
