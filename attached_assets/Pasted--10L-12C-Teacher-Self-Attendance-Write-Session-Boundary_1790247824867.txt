# 10L-12C — Teacher Self-Attendance Write Session Boundary Fix

We are continuing the existing Attendance hardening work.

**10L-12B is COMPLETE and must remain untouched.**

Implement **ONLY 10L-12C**.

## Objective

Fix the remaining Attendance defect identified in the 10L-12A audit:

> Teacher Self-Attendance check-in, check-out, and correction/write operations can currently accept/store a business date outside the selected Academic Session.

Every Teacher Self-Attendance mutation must verify that its attendance business date belongs to the **selected Academic Session**, using the already validated Session for the authenticated school.

### Required rule

For every Teacher Self-Attendance write:

```text
Academic Session start date <= attendance business date <= Academic Session end date
```

If the date is outside the selected Session:

* reject the mutation;
* do not create a record;
* do not update an existing record;
* do not bypass the existing mutation protections.

## Important existing requirements — MUST PRESERVE

1. **Multi-tenant isolation is mandatory.**

   * Never trust a client-supplied school ID.
   * The Session must belong to the authenticated Teacher's school.
   * Do not allow cross-school Session access or mutation.

2. **Academic Session is authoritative.**

   * Use the existing validated/selected Academic Session resolution already used by Attendance.
   * Do not create a second or competing Session-resolution mechanism.

3. **Archived Sessions remain read-only.**

   * Preserve the existing global mutation guard / Session mutation protection.
   * Do NOT weaken or bypass archived-Session protection.

4. **IST / Asia/Kolkata remains the application business timezone.**

   * Use the existing IST/date-only helpers.
   * Do not introduce UTC/local-server timezone conversions.

5. Preserve the existing:

   * Teacher Self-Attendance rate calculation.
   * Teacher Working Days configuration.
   * All_School holiday handling.
   * Targeted holiday behavior.
   * Present/Late/Half Day/Leave semantics.
   * Existing 7-day correction window.
   * Existing check-in/check-out behavior.
   * Existing authorization.
   * Existing database schema.
   * Existing historical Attendance records.
