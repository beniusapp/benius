---

1. Overall PDF Objective

The final PDF should look like a professional school financial ledger, not like a raw database export.

It should be:

- Clean
- Highly readable
- Compact but not cramped
- Suitable for A4 landscape printing
- Easy to audit
- Easy to scan row-by-row
- Professional enough to share with the Principal, accountant, auditor, or school management
- Consistent across multiple pages

The current PDF is technically correct, but the table is too dense and some text becomes difficult to read at normal phone/PDF-viewer zoom.

7. Column Widths

Use the full available table width intelligently.

Prioritize width for:

- Student
- Fee Name
- Fee Type
- Fee Period
- Payment Method
- Reference No.

Keep narrow identifiers such as Invoice No., Receipt No., and DSID relatively narrow.

Do NOT give excessive width to:

- Status
- Amount
- Paid
- Outstanding
- Due Date
- Paid On

Those values are short.

The final column widths must add up exactly to the available table width.

Add a programmatic assertion/check so accidental width overflow is caught during development.

---

8. Text Wrapping

This is very important.

Do NOT allow text to be clipped.

The following columns should support wrapping:

- Invoice No.
- Receipt No.
- Student
- DSID
- Fee Name
- Fee Type
- Fee Period
- Payment Method
- Reference No.

Long values should wrap to 2–3 lines when necessary.

Examples:

Random2Student

should remain readable.

A long reference such as:

pay_ABC123XYZ987654

should wrap rather than disappear outside the cell.

---

9. Dynamic Row Height

Do not use one fixed row height for every row.

Before rendering each row:

1. Measure the wrapped content.
2. Determine the tallest cell.
3. Calculate the row height from that cell.
4. Add reasonable vertical padding.
5. Render the complete row.

Short rows should remain compact.

Long rows should automatically become taller.

No text should overlap another row.

No text should be clipped.

No text should be rendered outside its cell.

---

10. Typography

Use a clear hierarchy.

Report title

Approximately:

15–16 pt bold

Column headers

Approximately:

7–8 pt bold

Normal table text

Approximately:

7–8 pt

Narrow identifier columns

Approximately:

6.5–7 pt

Do not make the entire table 5–6 pt just to fit everything.

Readability is more important than squeezing every column.

13. Status Display

Status should be visually obvious.

Use a small rounded status pill.

Examples:

Paid

Green/light-green background with dark green text.

Due

Amber/light-yellow background with dark amber text.

Overdue

Red/light-red background with dark red text.

Partial

Blue/light-blue background with dark blue text.

Waived

Grey background with dark grey text.

Do not rely on color alone; the status text must remain clearly readable.

14. Financial Amount Formatting

Use Indian currency formatting consistently.

Examples:

₹1,000
₹12,000
₹1,00,000

Do not display unnecessary decimal values such as:

unless the actual amount contains paise.

Align monetary values consistently, preferably right-aligned.

Columns:

- Amount
- Paid
- Outstanding

should be visually easy to compare.

15. Dates

For example:

20 Aug 2026

22. Important Audit Requirement

The PDF must make it immediately clear that:

Invoice amount ≠ amount paid ≠ outstanding amount.

For every invoice:

Outstanding = max(Invoice Amount − Total Paid, 0)

Do not change this calculation.

The status displayed must continue coming from the existing invoice status logic.

Do not derive or recalculate the status inside the PDF renderer.
