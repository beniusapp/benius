# 1. APPROVAL CENTER

For Approval Center, I DO want submodule permissions, but ONLY the REAL functional modules visible inside the actual Approval Center.

The actual Approval Center contains:

- Gallery Hub
- E-Book Library

Therefore Support Staff permission control must show exactly:

```text
☐ Approval Center
   ☐ Gallery Hub
   ☐ E-Book Library
```

Do NOT add artificial permissions for individual buttons/actions.

For example, do NOT create separate permissions such as:

- View
- Approve
- Reject
- Upload
- Delete
- History

The permission boundary is the REAL submodule.

---

## Gallery Hub

If Support Staff is granted:

**Approval Center → Gallery Hub**

then Support Staff gets the complete normal Principal/Admin operational functionality inside Gallery Hub.

Whatever Principal/Admin can normally manage inside Gallery Hub should be available to that Support Staff member, subject to normal security/business rules.

If Gallery Hub is NOT granted:

- do not expose Gallery Hub
- direct URL/access must be blocked
- Gallery Hub management APIs must reject Support Staff

---

## E-Book Library

If Support Staff is granted:

**Approval Center → E-Book Library**

then Support Staff gets the complete normal Principal/Admin operational functionality inside E-Book Library.

Example:

```text
Approval Center
   Gallery Hub      ❌
   E-Book Library   ✅
```

Support Staff should be able to fully manage the normal E-Book Library workflow like Principal/Admin, but should NOT gain Gallery Hub access.

If E-Book Library is not granted, its UI/direct access/protected APIs must reject Support Staff.
