# BENIUS EXAMINATION — STAGE 1 ACCESS SIMPLIFICATION
## Allow Same-School Teachers to Add Marks
### CONTROLLED IMPLEMENTATION — BEFORE STAGE 2B

The read-only audit has confirmed the root cause of the Web Teacher Add Marks error.

Current behavior:

Web `POST /api/exam-scores` rejects marks entry with HTTP 403 when the Teacher's Faculty Mapping or legacy assignment does not match the selected class, section and subject.

This restriction was introduced during Stage 1.

The owner has approved a simpler business rule.

## APPROVED BUSINESS RULE

Any authenticated, active Teacher belonging to the same school may add or correct examination marks for any valid class, section and subject in that school's active Academic Session.

Faculty Mapping and teaching assignment must NOT be required for Web Add Marks.

This is a school-wide Teacher marks-entry permission, NOT cross-school permission.

## 1. STRICT SCOPE

Implement only the Web Teacher Add Marks authorization correction.

Do not change:

- Mobile frontend.
- Mobile Teacher assignment checks.
- Mobile-specific backend routes.
- Teacher View Marks authorization.
- Teacher Results authorization.
- Teacher ledger Save/Lock authorization.
- Principal Exam Controller.
- Promotion execution.
- Principal overrides.
- Examination policy or grading.
- Academic Session activation.
- Student Registry placement.
- Existing examination records.

No Production access or deployment.

## 2. REMOVE ONLY THE WEB ASSIGNMENT GATE

Inspect Web `POST /api/exam-scores`.

Remove the requirement that the Teacher must have a matching Faculty Mapping or legacy teaching assignment for the selected class, section and subject.

Do not remove authentication or Teacher active-status validation.

Do not remove School ID validation.

Do not remove Academic Session validation.

Do not remove Student Enrollment validation.

Do not remove Subject or Exam Type configuration validation.

Do not remove marks validation.

Do not remove locked-ledger protection.

If the assignment check exists inside shared storage or helpers, ensure removing it does not weaken Mobile-specific checks or other endpoints.

Do not broaden the scope of unrelated Teacher APIs.

2. Active Teacher account.

6. Session is active and writable.
7. Selected Class and Section belong to that School.
8. Subject and Exam Type are valid for that School and class.
9. Each Student belongs to the same School.
10. Each Student has an Active Enrollment in the exact selected Academic Session and Class/Section.
11. Marks are valid and within the permitted range.
12. Duplicate or invalid batch submissions are rejected.
13. Existing locked-ledger safeguards still return HTTP 409 where applicable.
14. Successful Web saves retain the approved immediate Student marks visibility behavior.
15. Existing Teacher attribution is preserved.

Never trust School ID or Teacher ID supplied by the client.
