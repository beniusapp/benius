STEP 2J — ATTENDANCE WORKING-DAY / CALENDAR CANONICALIZATION
READ-ONLY AUDIT ONLY — DO NOT MODIFY ANY FILE, DATABASE, SCHEMA, MIGRATION, OR RUNTIME BEHAVIOR

Context:
Attendance Steps 2D–2I are complete and passed.

Completed requirements that MUST remain unchanged:
- Multi-tenant school isolation is mandatory.
- Every Attendance operation is scoped to authenticated school/tenant.
- Every Attendance read/calculation is scoped to a validated Academic Session ID.
- Student Registry is global/permanent and must NOT reset/change when Academic Session changes.
- Historical Attendance must remain visible for the selected historical session.
- Historical class/section authority from Step 2H must remain unchanged.
- Enrollment is NOT an Attendance prerequisite.
- Faculty Mapping is NOT an Attendance restriction.
- Any authenticated Teacher belonging to the school may mark Student Attendance.
- Student/Admin/Teacher Student Attendance use the Step 2I canonical status semantics:
  Present = 1.0
  Late = 1.0
  Approved Leave = 1.0
  Half Day = 0.5
  Absent = 0
  Unknown = 0
  Missing/Not Marked = 0 but tracked separately from explicit Absent.
- Teacher self-attendance remains separate and is NOT part of this Step 2J calculation contract.
- Attendance history remains read-only for historical sessions.
- Application-facing dates/times must remain IST / Asia/Kolkata.
- Production must NOT be accessed or modified.

Purpose of Step 2J:
Determine exactly how "working days" are currently derived across Admin, Teacher, and Student Attendance, and identify the minimum changes required so all Student Attendance calculations use ONE authoritative school-calendar/working-day definition for the selected Academic Session.

IMPORTANT:
This is READ-ONLY ONLY.
Do NOT implement fixes.
Do NOT edit files.
Do NOT create migrations.
Do NOT change schema.
Do NOT restart the application unless absolutely required for read-only inspection.
Do NOT change existing behavior.
