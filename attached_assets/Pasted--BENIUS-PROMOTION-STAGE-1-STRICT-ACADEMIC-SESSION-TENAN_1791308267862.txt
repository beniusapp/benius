# KNOWN AUDIT FINDINGS

The previous audit confirmed:

### `/api/admin/promote`

- does not require/use source Academic Session strongly enough;
- receives Student IDs from client;
- history can be constructed before Student ownership is fully validated;
- `executePromotionTransaction()` marks decisions executed without session filter;
- Student profile update is school-filtered but history insertion can still accept a foreign-school Student ID;
- does not touch enrollments.

### Promotion Decisions

`promotion_decisions.sessionId` already exists but is nullable.

Teacher decision saving already uses a selected Academic Session.

However:

- reads can become cross-session when no session is supplied;
- execution update omits session;
- save conflict identity currently omits session.

IMPORTANT:

There is an existing known limitation:

**Promotion decision ledger unique/conflict identity lacks Academic Session.**

Current behavior may intentionally fail safely with `409` when a conflicting legacy/cross-session row exists.

Do NOT introduce a risky schema migration in this stage.

If proper session-aware uniqueness requires a database migration, preserve fail-safe behavior and report the limitation.
