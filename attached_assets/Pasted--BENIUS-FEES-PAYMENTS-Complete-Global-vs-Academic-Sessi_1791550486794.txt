# BENIUS — FEES & PAYMENTS
## Complete Global vs Academic Session Classification
### STRICT READ-ONLY AUDIT

Before continuing Examination Stage 3B-2, audit the CURRENT BENIUS Fees & Payments implementation.

Do not modify code, database records, schema, payments, receipts, invoices, configurations or permissions.

Do not deploy or access Production.

## OBJECTIVE

Determine exactly which Fees & Payments features are:

1. GLOBAL — school-wide and independent of Academic Session.
2. ACADEMIC SESSION BASED — explicitly bound to a selected Academic Session.
3. HYBRID — global configuration combined with session-specific financial records.
4. PARTIALLY SCOPED / UNSAFE — intended to be session-based but missing a necessary session check.

Do not infer classification from UI labels or the presence of an Academic Session selector.

Trace each feature through frontend, API, storage queries and database schema.
