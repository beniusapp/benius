## 1. EXACT REPORTED BUG

Example Student: Ram Jaiswal.

Academic Session 2026–2027:
- Student belongs to Class 1-A.
- Principal generates an invoice.
- Invoice, ledger and transactions operate correctly in that session.

Academic Session 2027–2028:
- Student is promoted to Class 2-A.
- Current Student Registry shows Class 2-A.

Now switch Principal Fees & Payments back to Academic Session 2026–2027 in read-only mode.

ACTUAL:
- Historical Fees records show Class 2-A.

EXPECTED:
- Historical Fees records should show Class 1-A.

The same incorrect historical class/section appears to affect:
- Principal Fees & Payments.
- Student Fees & Payments.
- Fees reports.

The owner has manually observed the issue.

Do not assume the exact root cause. Investigate and prove it from source code.

Do not change any records or code.

- Historical invoice should display Class 1-A.

- Historical reports should display Class 1-A.
