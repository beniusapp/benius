1. SIGNED BUT UNATTRIBUTABLE WEBHOOKS MUST NEVER DISAPPEAR
   ==================================================

This is mandatory.

A webhook can be:

- cryptographically valid
- genuinely signed by Razorpay
- structurally valid

but still impossible to safely associate with a school/invoice because:

- payment ID is unknown
- order ID is unknown
- notes do not contain tenant information
- notes contain unusable information
- payment/order identity conflicts
- the referenced provider identity belongs to no known tenant

In ALL of these situations:

DO NOT reject and discard the signed webhook merely because tenant attribution failed.

Instead:

1. Verify the Razorpay signature first.
2. Extract all safely available provider identifiers.
3. Attempt tenant resolution using the secure precedence already implemented.
4. If resolution is impossible or ambiguous:
   - retain the signed webhook as an immutable delivery receipt
   - tenant/school remains NULL
   - resolution_status = "unresolved" or equivalent
   - resolution_source = "none" / appropriate value
   - resolution_reason contains the exact reason
   - verified = true
   - provider event ID retained
   - provider event type retained
   - provider payment ID retained when available
   - provider order ID retained when available
   - provider event timestamp retained when supplied
   - application received timestamp retained
   - safe payload/reference retained according to the existing privacy model
5. Append processing-history entries describing the resolution attempt.
6. Do NOT modify any invoice.
7. Do NOT modify any payment record.
8. Do NOT create a receipt.
9. Do NOT assign the webhook to any school.

The important distinction is:

AUTHENTIC BUT UNRESOLVED

is NOT the same as:

INVALID / UNVERIFIED

Both must remain distinguishable.
