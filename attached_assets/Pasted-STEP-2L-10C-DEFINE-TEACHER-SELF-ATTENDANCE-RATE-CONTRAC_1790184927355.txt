STEP 2L-10C — DEFINE TEACHER SELF-ATTENDANCE RATE CONTRACT
DECISION / SPECIFICATION ONLY — NO CODE CHANGES

Context:
STEP 2L-10A and STEP 2L-10B audited Teacher Self-Attendance.

The audits established:

- Teacher Self-Attendance has an existing mechanism for recording attendance status.
- Existing Attendance Policy determines the stored status of a new Teacher Self-Attendance event.
- Historical stored Teacher status must not be reinterpreted when Attendance Policy changes later.
- Teacher Self-Attendance is school/tenant scoped.
- Teacher Self-Attendance is Academic Session scoped.
- Application/business/display date logic uses IST / Asia/Kolkata.
- However, there is currently NO authoritative business contract defining the Teacher Self-Attendance RATE/PERCENTAGE.
- Three existing implementations currently calculate the rate differently:
  1. Server Teacher Self-Attendance history
  2. Teacher My Attendance
  3. Teacher Attendance History

IMPORTANT:

This step is NOT an implementation step.

DO NOT modify source code.

DO NOT modify tests.

DO NOT modify database/schema.

DO NOT create migrations.

DO NOT modify UI.

DO NOT refactor anything.

DO NOT select an existing implementation as correct.

DO NOT silently copy Student Attendance rules.

DO NOT invent a business rule and treat it as already approved.

The purpose of this step is to create a clear Teacher Self-Attendance RATE CONTRACT that the project owner can review and explicitly approve.

==================================================
PROJECT-WIDE NON-NEGOTIABLE RULES
==================================================

1. MULTI-TENANT / MULTI-SCHOOL

All Teacher Self-Attendance data and calculations must remain isolated to the authenticated school/tenant.

Never permit or suggest:
- cross-school Teacher attendance
- cross-school calculations
- another school's Academic Session
- mixing attendance records between schools

2. ACADEMIC SESSION

Teacher Self-Attendance must remain explicitly associated with the selected school-owned Academic Session.

Do not mix records from different Sessions.

Do not use legacy null-Session rows in Session-scoped calculations.

The policy decision must explicitly state how the Session's start/end dates affect the rate.

3. IST

Application/business/display date logic must use:
Asia/Kolkata / IST

Do not introduce BST, UTC date semantics, or another local timezone for business-date decisions.

4. STUDENT ATTENDANCE IS SEPARATE

Do not assume that Student Attendance rules automatically apply to Teachers.

Student Attendance has its own established contract.

Teacher Self-Attendance requires a Teacher-specific contract.

5. CLASS TRANSFER

Do not reopen or discuss the previously skipped same-Session Student class-transfer issue.

6. PRODUCTION

Do not perform any production/deployment/migration work.

Decide whether each should:

- be excluded from denominator
- count as absent
- count as another status
- have another explicitly defined treatment
