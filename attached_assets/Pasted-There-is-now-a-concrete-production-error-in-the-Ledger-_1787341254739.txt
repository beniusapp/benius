There is now a concrete production error in the Ledger PDF selection flow.

I selected 3 invoice records in the Ledger & Transactions screen and clicked Ledger PDF.

The UI shows:

PDF download failed

"error: op ANY/ALL (array) requires array on right side"

The normal Ledger PDF without selection works correctly.

Therefore, DO NOT rewrite the PDF renderer and DO NOT touch the existing PDF layout.

This is specifically a backend PostgreSQL parameterization/type problem in the new POST selection endpoint.

1. Root problem

The new POST endpoint currently uses selection SQL equivalent to:

AND fr.id = ANY($parameter)

and:

AND fr.id != ALL($parameter)

The JavaScript value is an array, but PostgreSQL is receiving/binding the parameter in a way that is NOT being recognized as a PostgreSQL array.

PostgreSQL therefore throws:

op ANY/ALL (array) requires array on right side

Fix the parameterization so PostgreSQL receives a properly typed integer array.

---

2. Fix individual selection

The current logic is conceptually:

AND fr.id = ANY(${selectedIds})

Do NOT simply keep interpolating a JavaScript array as a normal query parameter.

Make the parameter explicitly a PostgreSQL integer array.

The final SQL must effectively behave like:

AND fr.id = ANY($1::integer[])

or use the correct array-parameter mechanism supported by the project's existing PostgreSQL/SQL library.

Use the project's existing SQL helper/query-builder conventions.

Do NOT invent a new database library.

---

3. Fix excludedIds as well

The same issue can occur with:

AND fr.id != ALL(${excludedIds})

Make sure "excludedIds" is also bound as a properly typed PostgreSQL integer array.

The final SQL must effectively behave like:

AND fr.id != ALL($1::integer[])

or an equivalent correctly typed PostgreSQL array expression.

Fix BOTH "ANY()" and "ALL()".

Do not fix only the "selectedIds" branch.
