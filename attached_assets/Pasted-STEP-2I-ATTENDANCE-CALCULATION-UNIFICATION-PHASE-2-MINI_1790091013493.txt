==================================================
AUTHORITATIVE CALCULATION CONTRACT
==================================================

The existing Student Attendance calculation semantics must become the single
authoritative contract.

IMPORTANT:

The audit identified the Student Statistics calculation as the most complete
existing Student Attendance interpretation because it explicitly defines
weights for recognized Student Attendance statuses.

Therefore preserve these EXISTING semantics unless the source code proves a
different explicit configured policy is already authoritative:

present = 1.0
late = 1.0
leave = 1.0
halfday / half_day = 0.5
absent = 0.0

Do NOT invent new weights.

Do NOT modify policy values.

Do NOT silently change these weights.

Unknown/unrecognized status MUST NOT be treated as present.

Unknown/unrecognized status must have weight 0 and must NOT receive positive
credit.

Missing Attendance must remain distinguishable from an explicitly stored
`absent` record.

Do not silently convert a missing record into a stored Attendance record.

==================================================
AUTHORITATIVE AGGREGATION HELPER
==================================================

Create ONE shared server-side Student Attendance aggregation helper.

Prefer placing it in:

server/storage.ts

unless an existing Attendance-specific shared calculation module is already
the established architecture.

Do not create duplicate formulas in Admin, Teacher, and Student routes.

The helper must:

- accept schoolId
- accept sessionId
- accept the relevant Student Attendance records/context
- normalize recognized status values
- calculate weighted attendance using the canonical weights
- distinguish missing records from explicit `absent`
- return consistent counts and percentage inputs
- remain tenant/session scoped

The helper must be deterministic and side-effect free.

It must NOT:
- write Attendance records
- change policies
- query another school
- combine Academic Sessions
- alter Student Registry
- require Enrollment

==================================================
STATUS NORMALIZATION
==================================================

Use one normalization path for Student Attendance statuses.

Recognized statuses:

present
absent
late
halfday
half_day
leave

Normalize equivalent half-day representations to one canonical internal
status.

Unknown status:

- weight = 0
- never count as present
- never silently become present

Preserve enough information in the returned aggregation to identify unknown
status data if existing callers expose status counts.

Do not delete or rewrite existing unknown-status records.

==================================================
MISSING ATTENDANCE SEMANTICS
==================================================

Do not collapse missing and explicit absent into the same stored status.

The aggregation helper must distinguish:

A. Explicit Attendance record with status `absent`

from

B. No Attendance record for the student/date.

For this step:

- explicit absent has weight 0 and increments explicit absent count
- missing has weight 0 but is tracked as missing/unmarked
- missing must NOT be silently rewritten into `absent`

The denominator must continue to follow the current Student Statistics
calculation's existing working-date input for now.

DO NOT change how working dates are generated.

That belongs to Step 2J.

==================================================

Preserve the existing Student Statistics percentage precision:

Do not change rounding behavior.

Do not change the source of applicableWorkingDays in Step 2I.

Step 2J will later make working-day derivation canonical.

If there are no applicable working days, preserve the existing safe behavior
rather than producing NaN or Infinity.
