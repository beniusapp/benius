IMPLEMENTATION PLAN ONLY — DO NOT MODIFY ANYTHING

We have completed a read-only audit of the Teacher/F​​aculty Mapping → Examination subject mismatch.

The audit confirmed:

- Faculty Mapping currently allows multiple subjects to be selected for one teacher + class + section.
- It serializes them into one comma-separated string, e.g.:
  "Bengali, Computer"
- That value is stored as ONE row in faculty_mappings.subject.
- Examination expects one canonical subject per authorization.
- Examination uses exact subject equality.
- Therefore:
  "Bengali" !== "Bengali, Computer"
  "Computer" !== "Bengali, Computer"

The recommended target architecture is:

Teacher
→ Class
→ Section
→ Subject

with ONE subject per mapping row.

Example:

Teacher 6 | Class 6 | Section B | Bengali
Teacher 6 | Class 6 | Section B | Computer

NOT:

Teacher 6 | Class 6 | Section B | "Bengali, Computer"
