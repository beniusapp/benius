## 1. BACKGROUND

The previous read-only audit identified:

- Normal school-logo uploads generate local paths such as `/uploads/schools/...`.
- The Ledger PDF generator accepts persisted absolute HTTP(S) logo URLs.
- Its `fetchBuffer` helper makes network requests without adequate destination restrictions, timeouts or response-size limits.
- The renderer may access internal/private network destinations.
- The renderer uses a URL assembled from the incoming request's protocol and Host header for relative logo paths.
- These behaviors create a potential SSRF and resource-exhaustion risk.

Relevant files reported by the audit:

- `artifacts/api-server/src/ledger-pdf.ts`
- `artifacts/api-server/src/fees-routes.ts`
- `artifacts/api-server/src/storage.ts`

Verify exact locations in the current source.

The normal school-logo upload functionality must remain unchanged.

## 2. OWNER'S REQUIRED BEHAVIOR

## 4. PHASE B — SECURE LOCAL LOGO RESOLUTION

Implement a narrowly scoped logo resolver for Ledger PDFs.

Accept only the supported application-managed logo path format, such as:

`/uploads/schools/<server-generated-filename>`

Use the actual format confirmed in Phase A.

Requirements:

- Reject absolute HTTP(S) URLs.
- Reject protocol-relative URLs.
- Reject unsupported URL schemes.
- Reject paths outside the approved school-logo directory.
- Reject traversal attempts, including encoded traversal.
- Reject unexpected path separators and malformed encodings.
- Reject paths containing query strings or fragments unless the existing trusted format explicitly requires them.
- Reject symbolic-link escapes.
- Reject non-regular files.
- Reject unsupported file types.
- Enforce a strict maximum file size before reading.
- Verify actual image content rather than trusting only the filename extension.
- Avoid following symlinks during file opening, using safe filesystem primitives where supported.
- Avoid time-of-check/time-of-use weaknesses when validating and opening files.

Do not construct local paths from arbitrary URLs.

Do not fetch external resources as a fallback.

If validation fails, return no logo and allow PDF generation to continue.

Use established project utilities where suitable.

## 5. PHASE C — REMOVE OUTBOUND LOGO FETCHING FROM LEDGER PDF
