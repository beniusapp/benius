# MY REQUIRED SIMPLE WORKFLOW

## STEP 1 — TEACHER ADDS MARKS

Inside Teacher Portal → Examination → Add Marks:

Teacher selects:

- Class
- Section
- Subject
- Exam Type
- Total Marks

Teacher enters marks for Students and saves.

The marks must be saved against the authenticated School and selected Academic Session.

Do not mix records from different sessions or schools.

## STEP 2 — MARKS APPEAR IN VIEW MARKS

After Teacher saves marks:

**Principal Portal → Performance Analytics → View Marks**

The latest saved marks must be visible without manual copying, synchronization jobs or duplicate marks tables.

**Student Portal → Examination → View Marks**

The same latest marks must become visible as soon as they are authorized for Student publication.

If the current system already has a marks-publication setting, preserve it and explain how it works.

If marks are already published and the Teacher makes an authorized edit, the updated published marks should appear promptly in both portals.

I want one authoritative marks source for all three portals.

Explain whether this can work with the existing APIs and database.

## STEP 3 — TEACHER RESULTS

Inside Teacher Portal → Examination → Results:

The system automatically calculates results from the saved examination marks.

Use the existing configured school examination policy, including:

- Applicable examination terms and components.
- Weightages.
- Pass percentages.
- Subject failure rules.
- Grade calculations.
- Promotion and retention suggestions.

Do not invent a new promotion policy.

A Student without applicable marks must remain Incomplete / Pending Result.

The Teacher reviews the calculated results.

After verification, the Teacher saves and locks the promotion ledger.

Do not allow incomplete or invalid results to be locked as final promotion decisions.

## STEP 4 — PRINCIPAL EXAM CONTROLLER

Inside Principal Portal → Exam Controller:

The Principal sees the Teacher's locked ledger.

The Principal reviews:

- Student
- Calculated result
- Teacher promotion/retention decision
- Eligibility and readiness
- Final destination Class/Section

The Principal makes the final authorized promotion/retention decision and executes it.

Preserve the existing secure backend promotion transaction.

The Principal must not be able to bypass incomplete marks, invalid locked decisions, School ID isolation or Academic Session validation.

Promotion execution prepares target-session Enrollment and history.

It must not directly rewrite current Student Registry placement.

Registry synchronization remains part of the existing authorized Academic Session activation process.

## STEP 5 — STUDENT RESULTS AND PRINCIPAL PERFORMANCE ANALYTICS

After the authorized result-publication and promotion workflow:

Student Portal → Examination → Results should show the appropriate published examination results and final promotion/retention outcome.

Principal Portal → Performance Analytics → Results should show the same authoritative academic results and promotion outcome.

Do not expose unpublished results to Students.

Do not confuse a Teacher's proposed promotion decision with the Principal's final executed decision.

# ACADEMIC SESSION — MANDATORY

All examination operations must be strictly scoped to:

1. Authenticated School ID.
2. Selected Academic Session ID.
3. Correct Class and Section.
4. Correct Student.
5. Correct Examination Term.

When a new Academic Session starts, it must have its own marks, results, ledgers and promotion context.

Historical records must remain preserved.

Archived Academic Sessions must be read-only.

Student Profile current Registry placement is a separate existing product rule and must not be changed.
