Step 6 — Optional Original Fee & Concession Snapshot

Implement Step 6 only based on the completed Steps 1–5.

Objective

Add an optional Original Fee to fee structures so that future invoices can historically record:

- Original Fee
- Concession Type
- Concession %
- Concession Amount
- Net Fee

while keeping the existing "fee_structures.amount" meaning unchanged.

CRITICAL RULE

"fee_structures.amount" currently means the final/net amount charged to the student.

DO NOT change this meaning.

Do NOT redesign the existing fee calculation system.

Do NOT automatically calculate the net fee from the concession percentage.

Do NOT modify existing fee amounts.

---

1. Add "original_amount" to "fee_structures"

Add an optional nullable integer column:

original_amount INTEGER NULL

Meaning:

«Original/gross fee before concession, if the school chooses to provide it.»

Examples:

No concession / no original fee

amount = 5000
original_amount = NULL

With concession

original_amount = 3500
amount = 3150
concessionType = merit
concessionPercent = 10

The system must NOT assume that "original_amount" exists for every fee structure.

---

2. Add concession snapshot to "fee_records"

Add a new JSONB column:

concession_snapshot JSONB NOT NULL DEFAULT '{}'::jsonb

This is a historical invoice-time snapshot.

Recommended shape:

{
  "original_amount": 3500,
  "concession_amount": 350,
  "concession_type": "merit",
  "concession_percent": 10
}

If no valid original fee/concession snapshot exists:

{}

Important

The snapshot must be written once when the invoice is created and must never depend on the current "fee_structures" value when the receipt is later opened.

---

3. Snapshot calculation rules

Create/update the invoice snapshot utility so it handles the following.

Case A — "original_amount" is not provided

Example:

original_amount = NULL
amount = 5000
concessionType = none
concessionPercent = 0

Store:

{}

Do NOT fabricate an original amount.

Case B — Original amount is provided

Example:

original_amount = 3500
amount = 3150
concessionType = merit
concessionPercent = 10

Calculate:

concession_amount = original_amount - amount

Result:

{
  "original_amount": 3500,
  "concession_amount": 350,
  "concession_type": "merit",
  "concession_percent": 10
}

Case C — No actual concession

If:

original_amount = amount

then:

concession_amount = 0

Do not display a ₹0 concession on the receipt.

The snapshot may still preserve the original amount and concession metadata.

---

4. Validation rules

When "original_amount" is provided:

Block the invoice if:

original_amount <= 0

or:

amount > original_amount

or either amount is not a finite integer.

The following must always be true:

original_amount - concession_amount = amount

Do NOT silently correct invalid values.

Do NOT modify "fee_records.amount".

Do NOT automatically change the admin-entered net amount.

Important

Do NOT require "original_amount" for existing or normal fee structures.

It is optional.

---

5. Update the admin Fee Structure UI

Modify the existing fee structure create/edit form.

Keep the existing field:

Amount (₹)

and keep its current meaning:

«Final / Net Amount charged to the student.»

Add a new optional field:

Helper text:

«Enter the fee amount before concession, if applicable.»

Example:

Amount: ₹3,150
Concession Type: Merit
Concession: 10%

Do NOT rename the existing Amount field to Original Fee.

Do NOT make Amount read-only.

Do NOT automatically calculate Amount from Original Fee.

The admin remains responsible for entering the final/net amount.

---

6. UI validation

If Original Fee is entered:

Original Fee >= Amount

If:

Original Fee < Amount

show a clear validation error and prevent saving.

If Original Fee is empty:

- allow saving
- preserve current behavior
- no concession snapshot should be created

Do not force schools to enter an Original Fee.

7. Update invoice-generation paths

Update only the three structure-based invoice generation paths:

1. Monthly auto-invoice cron
2. Auto-trigger invoice generation
3. Manual/bulk invoice generation

At invoice creation, read:

structure.original_amount
structure.concessionType
structure.concessionPercent
structure.amount

and create the immutable "concession_snapshot".

Admin-direct invoice paths

For:

- Offline payment auto-create invoice
- Admin single-invoice creation

there is no fee structure lookup.

Therefore:

concession_snapshot = {}

Do NOT add a fee-structure lookup just to create this snapshot.

---

8. Historical immutability

This is mandatory.

Suppose at invoice creation:

Original Fee = ₹3,500
Concession = Merit 10%
Net Fee = ₹3,150

Snapshot:

{
  "original_amount": 3500,
  "concession_amount": 350,
  "concession_type": "merit",
  "concession_percent": 10
}

Later the admin changes the fee structure to:

Original Fee = ₹4,000
Concession = Merit 20%
Amount = ₹3,200

The old invoice MUST continue showing:

Original Fee: ₹3,500
Concession: ₹350
Net Fee: ₹3,150

It MUST NOT show the new values.

The receipt must NEVER query "fee_structures" for historical concession information.

TOTAL AMOUNT PAID ₹3,210

fee_records.amount

as the authoritative Net Fee.

Use:

for the late fee.

Total remains:

Do NOT use the component breakdown to calculate the total.
