## 1. BUSINESS OBJECTIVE

BENIUS must have a simple Examination workflow:

1. Teacher enters examination marks.
2. Students and Principal view authorized marks.
3. BENIUS calculates examination results using the existing shared calculation engine.
4. Teacher reviews results and locks a promotion/retention recommendation.
5. Principal reviews the Teacher recommendation.
6. Principal makes the final promotion/retention decision, including authorized overrides when necessary.
7. Principal executes promotion or retention.
8. Final executed outcomes are displayed appropriately.
9. Academic Session history remains preserved.

The Principal must have final authority.

Teacher recommendations must never silently become final Principal decisions.

## 8. PROMOTION EXECUTION AND REGISTRY RULE

The approved BENIUS behavior is:

**Promotion execution prepares target Academic Session enrollments and promotion history. It does NOT immediately update the Student's current Registry Class, Section or Roll Number.**

The Registry is synchronized atomically only when the target Academic Session is activated.

Audit whether current code respects this contract.

Identify any promotion code that directly changes:

- `students.class`
- `students.section`
- `students.rollNumber`
- Current Registry placement fields.

Also audit:

- Duplicate target enrollments.
- Incorrect target class or section.
- Missing target enrollment.
- Transaction atomicity.
- Idempotency.
- Concurrent execution.
- Rollback behavior.
- Historical enrollment preservation.

Do not change these behaviors in Stage 3A.
