The purpose of this audit is to determine exactly how Attendance should

==================================================
CORE PRODUCT ARCHITECTURE — MUST PRESERVE
==================================================

The Student Registry is GLOBAL and PERMANENT.

Students are NOT recreated for every Academic Session.

The Student Registry must continue to exist independently of:

- Academic Session creation
- Academic Session switching
- Academic Session completion
- Academic Session deletion

Changing Academic Session must NOT reset the Student Registry.

Therefore:

A Student Registry record is NOT itself dependent on an Academic Session.

Do NOT reinterpret Enrollment as "creating/registering the student again."

==================================================
CURRENT INTENDED ATTENDANCE MODEL
==================================================

Attendance should fundamentally work like:

Student Registry
        ↓
Teacher Attendance roster
        ↓
Active Academic Session
        ↓
Attendance record

The Academic Session provides the academic context for the attendance
record.

The Student Registry provides the student identity.

Session-specific enrollment MAY contain additional academic information
such as:

- class
- section
- roll number
- session-specific placement

But DO NOT assume that enrollment must become a prerequisite for a
Student Registry student to exist or appear in the Attendance roster.

1. Global Student Registry

existence of the student.
