## 3. Mandatory Academic Session acceptance tests

This is the highest-priority part of FA-R7.

Test these scenarios:

### Scenario A — Active Academic Session

Select the active Academic Session.

Verify:

- Correct session name and ID.
- Correct financial cards.
- Correct charts.
- Correct aging details.
- Correct PDF session identity.
- No archived-session financial records appear.

### Scenario B — Archived Academic Session

Select an archived Academic Session.

Verify:

- Correct archived session name and ID.
- Financial Analytics remains readable.
- Financial cards reflect the archived session.
- Historical Class Performance uses archived enrollment.
- Aging drill-down shows historical Class and Section.
- PDF reflects the archived session.
- No current-session financial data contaminates the results.

### Scenario C — Refresh while archived session is selected

1. Select an archived session.
2. Refresh the page.
3. Wait for authorized sessions to load.
4. Confirm the same archived session is restored.
5. Confirm the dashboard loads that session's data.

This verifies the FA-R6 session restoration correction.

### Scenario D — Navigate away and return

1. Select an archived session.
2. Navigate to another Principal module.
3. Return to Financial Analytics.
4. Confirm the correct session remains selected.
5. Confirm its financial data is displayed.

### Scenario E — Rapid switching

Switch:

Active → Archived → Active → Archived.

Verify:

- Every request uses the captured Academic Session ID.
- Stale responses are not displayed under a different session.
- Charts and cards remain consistent.
- Aging drawer does not display previous-session data.
- No session-mismatched PDF is downloaded.

Do not claim a race condition was dynamically tested unless actual rapid switching was exercised.

### Scenario F — Multiple archived sessions

If more than one archived Academic Session exists:

- Switch Archived A → Archived B.
- Verify correct data and session labels.
- Refresh.
- Verify Archived B remains selected.

If the environment has only one archived session, mark this scenario NOT VERIFIED.

### Scenario G — Invalid saved session

Using safe, non-destructive test methods, verify that an invalid, deleted, or unauthorized stored session ID cannot become the selected session.

Do not modify the application's database or session records to manufacture this scenario.
