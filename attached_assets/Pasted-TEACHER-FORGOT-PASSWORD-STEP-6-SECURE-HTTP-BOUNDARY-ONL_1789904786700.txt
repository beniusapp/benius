==================================================
STEP 6 GOAL
==================================================

Securely connect the FIRST TWO HTTP stages:

1. POST /api/teacher/forgot-password
2. POST /api/teacher/verify-otp

The intended flow becomes:

Teacher submits:
School Code + Email

→ server validates school code
→ server obtains authenticated tenant context from school lookup
→ server creates secure Teacher recovery challenge
→ server creates OTP_PENDING recovery session
→ server sends OTP through the school's own notification configuration
→ generic response

Then:

Teacher submits:
OTP only

→ server reads challengeId/userId/schoolId/teacherId from server-side recovery session
→ server verifies OTP using Step 4
→ Step 4 generates a fresh reset token
→ server stores that reset token in server-side recovery session using Step 5
→ generic success response

The browser must NEVER receive:

- teacherId
- userId
- schoolId
- challengeId
- resetToken
