# PART 2 — DEFINE THE INCOMPLETE RESULT CONTRACT

Approved behavior:

**No marks = Incomplete / Pending Result.**

Investigate how to represent this state consistently across:

- Teacher Results
- Weighted Average
- Grade
- Subject Failures
- Promotion Gate
- Auto-Suggestion
- Save Draft
- Lock & Save Ledger
- Student Report
- Admin Exam Controller
- Promotion execution
- Student-facing published results, where relevant

### Critical distinctions

Determine how the current calculation engine represents:

1. No subject scores at all.
2. A configured subject with no marks.
3. A subject with one required assessment component missing.
4. A Student explicitly marked Absent.
5. A Student who legitimately scores zero.
6. A Student with partial term data.
7. A Student with all required assessment components completed.

Do not automatically equate all these cases.

The approved no-marks rule is definitive.

For partially completed results, identify the current semantics and propose whether they should also be considered Incomplete, but DO NOT silently change the business rule.

### Required proposed UI behavior

For a Student with no marks:

- Weighted Average: No data
- Grade: —
- Result Status: Incomplete / Pending Result
- Promotion Gate: Pending — No marks
- No automatic promotion
- No automatic retention

Determine how this can be represented without inventing a fake numeric score or grade.

Identify whether an additive database state or schema migration is required.
