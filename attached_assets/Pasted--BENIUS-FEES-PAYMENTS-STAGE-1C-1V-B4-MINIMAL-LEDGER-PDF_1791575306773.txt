## 3. PHASE B — DEFINE AND IMPLEMENT FAIL-CLOSED SELECTION

Only after Phase A passes.

For `POST /api/admin/fees/ledger/pdf`, preserve the existing documented request shape while enforcing the following contract.

### Mode 1 — Explicit selected invoice IDs

When `selectAllMatching` is false:

- Require an array of selected invoice IDs.
- Require at least one ID.
- Accept only positive safe integer IDs, using the actual database ID type and existing API representation.
- Reject malformed IDs.
- Reject zero and negative IDs.
- Reject duplicate IDs rather than silently changing the selection.
- Reject missing IDs.
- Reject empty arrays.
- Reject mixed valid and invalid IDs.
- Never interpret an invalid explicit selection as an all-matching export.

Use a clear 400 validation response for malformed requests.

### Mode 2 — Select all matching

When `selectAllMatching` is explicitly true:

- Preserve the existing all-matching export behavior.
- Preserve the existing filter contract.
- Preserve the existing excluded-ID semantics.
- Validate exclusions against the applicable ID type.
- Reject malformed exclusions.
- Do not silently change the requested export population.

Do not reinterpret an omitted or malformed `selectAllMatching` value as permission to export everything.

If existing callers rely on a different documented contract, report the incompatibility before implementing a breaking change.

### Authorized population validation

For explicit selected IDs:

1. Determine the authorized population using the existing school, session and filter restrictions.
2. Verify that every requested ID belongs to that population.
3. If any ID is unauthorized, belongs to another school/session, does not match filters, or does not exist, reject the entire selection.
4. Do not silently omit unauthorized IDs.
5. Do not disclose whether a rejected ID belongs to another school.
6. Do not return a partial PDF for a mixed selection.

Use an appropriate generic 400/403 response consistent with existing API conventions.

For select-all exclusions, preserve the existing contract and validate any supplied exclusions without leaking foreign-school information.

**No selected invoice may be retrieved outside the authenticated school and selected Academic Session.**
