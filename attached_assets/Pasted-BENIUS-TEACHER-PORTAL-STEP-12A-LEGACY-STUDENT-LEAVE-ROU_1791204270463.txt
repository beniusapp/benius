CONFIRMED PROBLEM

The audit found that this legacy route:

"GET /api/student-leaves/:schoolId/:class/:section"

currently verifies that the authenticated Teacher belongs to the requested school, but it does NOT adequately enforce:

- explicitly selected Academic Session
- Teacher assignment to the requested class/section
- Student enrollment in that selected Academic Session

It can therefore return pending Student Leave requests across sessions/classes, including legacy NULL-session rows.

The current Web Teacher Leave screen uses:

"/api/student-leaves/teacher/mine"

and no current Web/Mobile consumer of the legacy route was found.

Nevertheless, the legacy endpoint remains registered and directly callable, so it must not remain an authorization/session bypass.
