==================================================
FINDING BEING FIXED
==================================================

The read-only audit identified a cross-Academic-Session leak in:

  server/storage.ts
  getStudentMonthlyAttendance()

Attendance records are correctly filtered by:

- schoolId
- sessionId
- studentId
- month/date range

However, the separately queried approved Student Leave records are currently filtered by:

- schoolId
- studentId
- approved status
- overlapping date range

The approved-leave query does NOT require:

  studentLeaveRequests.sessionId = selectedSessionId

The monthly Attendance response then uses those approved leaves to display Leave when no Attendance record exists.

Therefore:

Session A approved leave
        ↓
same student/date
        ↓
Session B monthly Attendance
        ↓
Leave can incorrectly appear

This is a direct Session-isolation defect.

==================================================
REQUIRED CHANGE
==================================================

Modify ONLY the approved Student Leave lookup used by:

  getStudentMonthlyAttendance()

so that approved leave is restricted to the SAME validated selected Academic Session used by the Attendance query.

The leave query must be scoped to:

- authenticated/validated school
- selected student
- approved status
- requested date range
- selected Academic Session

Use the existing Student Leave session field and existing schema/storage conventions.

Do not introduce a new field.

Do not infer Session from dates.

Do not use the active/latest Session as a fallback.

Do not change the Attendance working-day rule.

Do not change Attendance status weights.

Do not change Attendance calculation logic.

==================================================
TENANT ISOLATION
==================================================

Preserve existing tenant isolation.

The approved leave query must remain school-scoped.

Never trust a browser-supplied schoolId to establish ownership.

Do not weaken any existing Student Leave authorization.

==================================================
HISTORICAL SESSION BEHAVIOR
==================================================

For a selected historical Session:

- approved leave belonging to that historical Session may appear
  according to the existing monthly Attendance display behavior.

For another Session:

- that leave must NOT appear.

Example:

Student 100
School 1

Session A:
  approved leave: 2026-07-10

Session B:
  no leave: 2026-07-10

When viewing Session A:
  2026-07-10 may show Leave.

When viewing Session B:
  2026-07-10 must NOT show Leave because of Session A's leave.
