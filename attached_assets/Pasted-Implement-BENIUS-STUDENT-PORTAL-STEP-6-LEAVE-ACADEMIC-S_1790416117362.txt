# 4. LEAVE CREATION

Leave creation is a current operational write.

Use the Step 1 current-write rule or equivalent safe behavior.

A new Student leave request must:

1. authenticate the Student
2. derive Student school server-side
3. validate the selected Academic Session
4. require that selected session to be the active/current session where that is the existing BENIUS leave-write rule
5. save the exact validated active Academic Session ID

Do NOT silently replace an invalid/historical/foreign selection with the active session.

If the Student selected an archived Academic Session:

new leave creation must be rejected.

If no selected session is supplied and the current UI always has a session selection, fail safely rather than inventing an unscoped write.

Preserve existing leave date/business validations.
