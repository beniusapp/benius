# BENIUS — STAGE FA-R9B
## STUDENT ENROLLMENT, ACADEMIC SESSION, CLASS/SECTION DISPLAY & PDF VERIFICATION

### STRICT READ-ONLY AUDIT — NO CHANGES AUTHORIZED

BENIUS is a multi-tenant School Management Information System.

The owner requires that every student-related Class and Section displayed within Financial Analytics correspond to the student's enrollment in the selected Academic Session.

This requirement applies to both:

1. Financial Analytics UI.
2. Every applicable Financial Analytics PDF export.

This stage is verification only.

## 1. Mandatory historical enrollment rule

For every student-related financial record, resolve placement using:

- Authenticated School ID.
- Student ID.
- Selected Academic Session ID, consistent with the financial record's invoice session.

The resulting Class and Section must come from that student's enrollment in the corresponding Academic Session.

Do not use the student's current Student Registry Class/Section when viewing a previous Academic Session.

Do not use a different Academic Session's enrollment.

Do not infer historical placement from the student's current class.

Do not fall back to current Registry placement if historical enrollment is missing or ambiguous.

## 2. Verify the complete data relationship

Trace the actual application code:

Authenticated School ID
→ Selected Academic Session ID
→ Fee Record / Invoice
→ Student ID
→ Enrollment matching School ID + Student ID + Invoice Academic Session ID
→ Historical Class and Section
→ Financial Analytics API response
→ UI display
→ PDF export.

Verify that the Student ID comes from the correct invoice/student relationship.

Verify that a fee record from one Academic Session cannot accidentally resolve an enrollment from another session.

Verify that a student from School B cannot be joined to an enrollment from School A.

Identify exact file paths, functions, SQL predicates, and line numbers.

## 3. Verify active-session display

Use a synthetic example:

## 4. Verify archived-session display

- Student-level Class must be 1.

- Aging drawer must show Class 1-A when applicable.
- Applicable PDFs must use the correct archived-session class.

Verify that Class 2-B does not appear as the historical placement for this student.

Verify that changing the selected session refreshes or correctly invalidates class-dependent data.
