# PRODUCT DECISION

For Support Staff, I do NOT want submodule-level permissions for Timetable Master or School Calendar.

These two modules must use a very simple:

**FULL MODULE ACCESS ON / OFF**

model.

---

# 1. TIMETABLE MASTER

Currently Support Staff permissions contain:

- Timetable Master
  - Schedule Grid
  - Bell Structure
  - Publish Timetable

REMOVE these submodule permissions from the Support Staff permission editor.

The permission editor should simply show:

```text
☐ Timetable Master
```

No expand arrow.

No Schedule Grid permission.

No Bell Structure permission.

No Publish Timetable permission.

## When Timetable Master is granted

Support Staff gets the **complete Timetable Master functionality available to Principal/Admin**, including:

- Schedule Grid
- Bell Structure
- Publish
- normal create/edit/update/delete actions available inside the module
- all normal Timetable functionality required by the module

Do not artificially disable buttons/actions merely because the user is Support Staff.

The module grant itself is the authorization.

Conceptually:

```text
Timetable Master = GRANTED
        ↓
Full Timetable Master access
        ↓
Schedule Grid ✅
Bell Structure ✅
Publish ✅
```

## When Timetable Master is NOT granted

Support Staff must have:

- no dashboard tile
- no direct URL access
- no Timetable API access
- no create/edit/delete/publish access

```text
Timetable Master = NOT GRANTED
        ↓
ZERO Timetable Master access
```

# VERY IMPORTANT — SAME AS PRINCIPAL FUNCTIONALITY

However, this does NOT mean bypassing security.

Always preserve:

- authenticated school/tenant isolation
- Academic Session rules where applicable
- historical-session read-only rules
- server-side authorization

```text

```
