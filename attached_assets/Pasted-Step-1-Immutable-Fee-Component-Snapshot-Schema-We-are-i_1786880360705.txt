---

1. Current Problem

The current system stores fee components only in:

"fee_structures.breakdown"

The existing structure is:

Array<{
  name: string;
  purpose: string;
  amount: number;
}>

This is a live configuration.

The forensic audit confirmed that:

- "fee_structures.breakdown" is NOT copied to "fee_records"
- "fee_records" currently has no component snapshot field
- historical invoices therefore have no immutable component information
- the student receipt currently correctly does NOT display historical fee components
- reading "fee_structures.breakdown" from the receipt would be incorrect because administrators can change the fee structure after invoice generation

We need to create the database capability to safely store the component breakdown at invoice creation time in a later implementation step.

---

2. Required Schema Change

Add exactly one new column to "fee_records":

breakdown_snapshot

Database type:

JSONB

It must be:

NOT NULL

with a default of:

[]

Conceptually:

breakdown_snapshot JSONB NOT NULL DEFAULT '[]'::jsonb

The stored shape must be:

Array<{
  name: string;
  purpose: string;
  amount: number;
}>

Use the existing project's naming conventions and Drizzle schema conventions.

5. VERY IMPORTANT — NO HISTORICAL BACKFILL

Existing "fee_records" must remain historically honest.

For all existing invoices:

Do NOT do this:

Do NOT query the current fee structure and populate old invoices.

Do NOT attempt to determine which fee structure originally created an invoice.

Do NOT reconstruct historical component values.

This would violate the project's immutable financial-history requirement.

The default "[]" is intentional.
