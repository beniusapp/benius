We are continuing the Attendance hardening work.

STEP 2L READ-ONLY AUDIT RESULT:
NEEDS CHANGES

This implementation step addresses ONLY Finding 1 from the audit:

Student Attendance currently maintains an independent local Academic Session selection instead of consistently following the portal's shared selected Academic Session.

IMPORTANT:
This step is narrowly scoped.

DO NOT:
- fix any other Step 2L findings
- modify Attendance calculation logic
- modify working-day logic
- modify Attendance database schema
- create or apply migrations
- modify Student Registry
- modify Enrollment behavior
- modify Faculty Mapping behavior
- modify Teacher Attendance
- modify Teacher self-attendance
- modify Admin Attendance
- modify leave synchronization
- modify Attendance policy validation
- introduce historical mutation locking
- make unrelated fixes
- refactor unrelated code

==================================================
REQUIREMENT
==================================================

Student Attendance must use the portal's shared Academic Session context as its authoritative selected Session.

The Student Attendance page must NOT maintain a competing Session authority.

The selected Session used by:

- Monthly Attendance
- Yearly Attendance
- Attendance Statistics
- Attendance-related policy requests
- Attendance query/cache identity

must correspond to the portal's selected Session.

If the portal has not yet resolved a selected Session, Session-dependent Attendance requests must not silently fall back to the active Session.

Do not invent a new Session-selection mechanism.

Reuse the existing session-view/context infrastructure.

==================================================
CURRENT AUDIT FINDING
==================================================

The audit identified:

File:
  client/src/pages/student-attendance.tsx

The component already reads:

  const { isArchiveMode, selectedSession } = useSessionView();

but also maintains:

  const [selectedSessionId, setSelectedSessionId] = useState<number | null>(null);

The local Session state currently becomes an independent authority.

The Session selector is also only exposed in the Yearly tab.

This can cause the Attendance page to use a different Session from the portal context.

==================================================
REQUIRED CHANGE
==================================================

Make the shared portal Session authoritative.

Use:

  useSessionView().selectedSession

as the source of truth for Student Attendance.

Remove the competing local Session authority if it is no longer required.

If a local UI selector is genuinely necessary for an existing UX reason, it must update/use the shared Session context rather than create a second independent Session authority.

Do NOT redesign the portal Session selector.

==================================================
SESSION-LOADING BEHAVIOR
==================================================

When selectedSession is not yet resolved:

DO NOT:
- silently use the active Session
- silently use a locally initialized Session
- request Attendance for an arbitrary Session

Instead, keep the Session-dependent query disabled/not executed until the shared selected Session is available.

Use the existing repository conventions for React Query's enabled/disabled behavior.

Do not add a new loading architecture.

==================================================

Do not introduce the historical mutation lock in this step.

Do not change backend authorization in this step.

Do not change how historical Attendance is calculated.
