## NON-NEGOTIABLE BENIUS REQUIREMENTS

---

These requirements must remain true throughout the audit and all future mobile development.

### 1. MULTI-TENANT / MULTI-SCHOOL ISOLATION

BENIUS is permanently multi-tenant / multi-school.

Every authenticated mobile operation must remain bound to the authenticated school/tenant.

A mobile client must NEVER be able to:

* switch to another school by changing an ID
* read another school's students
* read another school's teachers
* read another school's attendance
* read another school's examination data
* read another school's fees
* read another school's timetable
* read another school's policies
* read another school's academic sessions
* read another school's administrative data

Do not weaken or bypass existing school authorization.

Do not propose client-controlled school IDs as an authorization mechanism.

The backend must remain the source of truth for school identity.

### 2. ACADEMIC SESSION ISOLATION

BENIUS uses Academic Sessions.

Academic Session ID must remain explicitly respected by all session-sensitive operations.

Especially remember the strict requirement for:

Admin → Exam Controller

Every Exam Controller operation must remain scoped to:

* authenticated school/tenant
* selected Academic Session ID

A new Academic Session must have a fresh and isolated Exam Controller context.

Previous-session operational data must not leak into a new session.

Do not propose authentication changes that bypass Academic Session handling.

### 3. IST

Application/business/display time must use:

`Asia/Kolkata`

Do not introduce browser/device timezone behavior for BENIUS business dates or displayed application timestamps.

### 4. WEB APPLICATION MUST KEEP WORKING

The existing web application must continue using its current authentication mechanism unless a future implementation plan explicitly provides backward-compatible changes.

Do not replace the web authentication system during this audit.
