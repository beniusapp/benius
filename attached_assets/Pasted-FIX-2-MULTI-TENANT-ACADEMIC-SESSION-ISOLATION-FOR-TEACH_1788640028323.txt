============================================================
NON-NEGOTIABLE SYSTEM REQUIREMENT — MULTI-TENANCY
============================================================

THIS APPLICATION IS A TRUE MULTI-TENANT SCHOOL MIS.

Each school is a separate tenant.

Tenant isolation is mandatory and must be preserved in every change.

A user/teacher belonging to School A must NEVER be able to:

- retrieve School B students
- retrieve School B examination scores
- retrieve School B academic sessions
- retrieve School B examination policies
- retrieve School B grading rules
- retrieve School B results
- calculate School B results
- save/update School B examination data
- use School B's session with School A data
- use School B's policy with School A data
- mix School A and School B data in any calculation

The authenticated user's/teacher's school is the authoritative tenant boundary.

Never trust a client-supplied schoolId as authorization by itself.

Every server-side operation must derive or validate the tenant from authenticated context.

This requirement applies to FIX 2 and ALL future fixes.

============================================================
PRIMARY GOAL
============================================================

Make Academic Session a real, validated data boundary for:

Teacher Portal → Examination

The selected Academic Session must not merely be UI context.

It must determine which examination score records are retrieved and supplied to the shared calculation engine.

The intended flow is:

    Authenticated Teacher
            ↓
    Authenticated Teacher's School/Tenant
            ↓
    Selected Academic Session
            ↓
    Validate session belongs to that tenant
            ↓
    Class / Section / Subject / Exam Type
            ↓
    Retrieve ONLY:
        authenticated school
        +
        selected session
        +
        existing relevant filters
            ↓
    Shared Examination Calculation Engine
            ↓
    Correct session-specific result

============================================================
SECURITY MODEL
============================================================

For every relevant Teacher Examination request:

    authenticatedTeacher.schoolId
             ↓
       authoritative tenant

The requested Academic Session must satisfy:

    academicSession.schoolId
        =
    authenticatedTeacher.schoolId

If not:

    reject the request.

Do NOT merely check that a session exists.

Do NOT allow:

    Teacher from School A
        +
    Session belonging to School B

Do NOT allow the frontend to select a School B session and then use it.

Do not leak whether another school's session exists.

Use the application's existing authorization/error conventions.
