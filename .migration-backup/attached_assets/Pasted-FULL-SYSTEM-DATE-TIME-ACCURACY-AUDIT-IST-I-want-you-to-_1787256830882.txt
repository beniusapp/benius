3. RAZORPAY TIMESTAMP AUDIT

This is especially important.

Audit every Razorpay timestamp.

Razorpay timestamps such as:

- "created_at"
- authorized time
- captured time
- failed time
- refund time
- dispute time
- webhook event time

must be interpreted correctly.

Verify that Razorpay Unix timestamps are converted correctly from their actual epoch representation.

Do NOT add +5:30 manually to a timestamp that has already been converted into a timezone-aware date.

For every Razorpay lifecycle event determine:

Provider timestamp

The actual time reported by Razorpay.

Application received timestamp

The exact time our server received/processed the webhook.

These are different facts and must remain separate.

For example:

Provider Event Time:
21 Aug 2026, 10:15:32 IST

Received by Application:
21 Aug 2026, 10:15:34 IST

Do not replace one with the other.

16. DST / TIMEZONE SAFETY

India does not observe daylight saving time.

Use:

Asia/Kolkata

rather than hardcoding a generic "IST" abbreviation internally.

Do not rely on:

IST

as a machine timezone identifier.

The canonical timezone should be:

Asia/Kolkata
