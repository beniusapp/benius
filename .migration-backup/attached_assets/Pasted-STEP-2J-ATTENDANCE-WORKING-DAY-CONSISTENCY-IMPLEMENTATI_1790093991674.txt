STEP 2J — ATTENDANCE WORKING-DAY CONSISTENCY
IMPLEMENTATION — MINIMUM SCOPE ONLY

IMPORTANT:
Implement ONLY the working-day rule described below.

Do NOT introduce a new school-calendar system.

==================================================
1. AUTHORITATIVE BUSINESS RULE
==================================================

For Student Attendance calculations, a "working Attendance day" means:

For the PARTICULAR school + Academic Session + CLASS + SECTION being calculated:

- At least one Attendance record exists for that class/section on that date
- AND the Attendance date falls within the selected Academic Session startDate and endDate

In simple terms:

Attendance record exists for this class/section
+
date is inside the selected Academic Session
=
applicable Attendance day

If no Attendance record exists for that particular class/section/date,
that date is NOT an applicable Attendance day.

IMPORTANT:

Attendance from another class/section MUST NOT make the date a working
Attendance day for this class/section.

Example:

School A
Session 2025-26
Date: 10 July

Class 6-A → no Attendance record
Class 7-A → Attendance record exists

Result:

Class 6-A → 10 July is NOT an applicable Attendance day
Class 7-A → 10 July IS an applicable Attendance day

==================================================
2. ACADEMIC SESSION BOUNDARY
==================================================

The selected Academic Session is mandatory.

Only Attendance dates satisfying:

session.startDate <= attendance.date <= session.endDate

may become applicable Attendance dates.

Example:

Session:
2025-04-01 → 2026-03-31

Attendance on:
2025-04-01 → included
2026-03-31 → included
2026-04-01 → excluded
2025-03-31 → excluded

The Attendance record's:

- school_id
- session_id
- class
- section
- date

must be respected.

Never infer the Academic Session from the date alone.

==================================================
3. TENANT ISOLATION
==================================================

Every calculation MUST remain scoped to the authenticated school/tenant.

Use:

authenticated school
+
selected validated Academic Session
+
selected historical/current class/section

Never allow Attendance from another school to influence the working-day set.

Browser-supplied schoolId MUST NOT be trusted as the ownership authority.

Preserve all Step 2G tenant protections.

==================================================
4. CLASS / SECTION ISOLATION
==================================================

Working dates must be determined for the PARTICULAR class/section being calculated.

DO NOT use:

- another class's Attendance records
- school-wide Attendance dates
- another section's Attendance records
- current Student Registry placement to replace historical context

Preserve Step 2H historical class/section authority:

1. Selected-Session Enrollment
2. Attendance class/section snapshot fallback

Enrollment is NOT an Attendance prerequisite.

Faculty Mapping is NOT an Attendance restriction.

==================================================
5. STEP 2I STATUS RULES MUST NOT CHANGE
==================================================

Keep the existing Step 2I contract exactly:

Present = 1.0
Late = 1.0
Approved Leave = 1.0
Half Day = 0.5
Absent = 0
Unknown = 0
Missing / Not Marked = 0, tracked separately

Step 2J is ONLY about determining which dates are applicable.

Do NOT change status weighting.

==================================================
6. SINGLE WORKING-DATE SOURCE
==================================================

Create or reuse ONE server-side helper responsible for determining
applicable Attendance dates.

Suggested location:

server/student-attendance-working-days.ts

Suggested responsibility:

getStudentAttendanceWorkingDates({
  schoolId,
  sessionId,
  class,
  section,
  startDate,
  endDate
})

The helper must:

1. Validate that sessionId belongs to schoolId.
2. Read session.startDate and session.endDate.
3. Intersect the requested date range with the Session boundaries.
4. Find DISTINCT Attendance dates for:
   - school_id = authenticated school
   - session_id = selected Session
   - relevant class
   - relevant section
5. Return unique, sorted SQL date strings.

The helper must NOT depend on:

- calendar_events
- Sunday/Saturday rules
- holidays
- school closures
- special working-day rules
- current Student Registry class/section
- whether an individual Student has an Attendance record
- Enrollment as an eligibility gate
- Faculty Mapping

The class-level Attendance dates are the working-day evidence.

==================================================
7. STUDENT ATTENDANCE
==================================================

Update the applicable Student Attendance calculations so they use the
same working-date helper.

Relevant functions include:

- getStudentYearlyAttendance()
- getStudentAttendanceStats()
- getStudentAttendanceAggregatesForSessionClass()

The calculation order must be:

STEP 1:
Determine applicable Attendance dates for the selected
school + Session + class + section.

STEP 2:
For each applicable date, determine each Student's status:

- Attendance row exists → use its status
- Attendance row does not exist → Missing/null

STEP 3:
Pass those statuses to the existing Step 2I aggregator.

IMPORTANT:

A Student having no Attendance record must NOT cause the entire date
to disappear if another Student in the SAME class/section has an
Attendance record for that date.

Example:

Class 6-A has 30 students.

10 July:
20 students have Attendance records.
10 students have no Attendance records.

10 July IS an applicable Attendance day for Class 6-A.

The 10 students without records are Missing/null.

They must NOT make 10 July disappear.

==================================================

- Special working-day overrides

This is intentional.

==================================================
12. APPROVED LEAVE
==================================================

Do NOT change Leave behavior.

If an approved Leave request has no Attendance record:

- it does NOT create a working Attendance day
- it remains Missing for Attendance calculation purposes

If an Attendance record explicitly has status "leave", the existing
Step 2I rule applies:

Leave = 1.0

Do not modify Leave synchronization.

14. SESSION ISOLATION
==================================================

If two Academic Sessions contain Attendance on the same date:

Session A Attendance must NOT become working-day evidence for Session B.

The query MUST include:

school_id = authenticated school
AND
session_id = selected Academic Session

The Attendance record's session_id is authoritative.
