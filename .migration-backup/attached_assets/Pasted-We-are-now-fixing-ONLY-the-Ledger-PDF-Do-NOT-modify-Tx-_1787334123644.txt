However, there is one important functional problem:

CURRENT PROBLEM

The Ledger PDF completely ignores the selection state.

The frontend currently has this selection model:

selectedIds      — Set<number>
selectAllMatching — boolean
excludedIds      — Set<number>

The meaning is:

Mode 1 — Individual selection

selectAllMatching = false
selectedIds = {A, B, C}

Only A, B and C are selected, even if they are spread across different pages.

Mode 2 — Select All Matching

selectAllMatching = true
excludedIds = {}

This means:

«ALL records matching the current search/filter/session scope are selected.»

No thousands of IDs should be materialized into "selectedIds".

Mode 3 — Select All Matching with exclusions

selectAllMatching = true
excludedIds = {99, 145}

This means:

«All matching records EXCEPT invoice IDs 99 and 145.»

The Ledger PDF must respect this exact model.

REQUIRED LEDGER PDF BEHAVIOR

Implement the following behavior.

CASE 1 — Nothing selected

If:

selectedIds.size === 0
selectAllMatching === false

then Ledger PDF should behave exactly as it currently does.

It should export:

«ALL records matching the current Ledger toolbar filters and academic session.»

Existing filters must continue working:

- Search
- Status
- Class
- Fee Name
- Fee Type
- Academic Session

Pagination must have NO effect.

---

CASE 2 — Individual invoices selected

Example:

selectedIds = {101, 205, 310}
selectAllMatching = false

When the admin clicks Ledger PDF, export ONLY:

101
205
310

Do not export all matching invoices.

The selected invoices may exist across different pages.

Example:

Page 1 → invoice 101 selected
Page 2 → invoice 205 selected
Page 5 → invoice 310 selected

Ledger PDF must contain all three.

Do NOT depend on the currently visible page.

---

CASE 3 — Select All Matching

Example:

selectAllMatching = true
excludedIds = {}

The Ledger PDF must export:

«Every invoice matching the current search/filter/session scope.»

Do NOT download all records into the browser.

Do NOT populate "selectedIds" with thousands of IDs.

The backend should query the matching records directly.

---

CASE 4 — Select All Matching + exclusions

Example:

selectAllMatching = true
excludedIds = {99, 145}

The Ledger PDF must export:

«Every matching invoice EXCEPT invoice IDs 99 and 145.»

This is extremely important.

Do NOT convert the selection into a list of thousands of IDs.

The SQL should continue using exclusion semantics, for example:

fr.id NOT IN (...)

only for the relatively small "excludedIds" set.

---

CASE 5 — Filters + selection

Selection must work together with the current filters.

For example:

Search = "student3mis"
Class = "6A"
Status = "Overdue"
selectedIds = {12, 25, 81}

The final result must be:

«Selected IDs that also satisfy the active Ledger filters.»

Do not allow an invoice outside the current session/school/security scope to be exported merely because its ID was supplied.

The backend must always enforce:

school_id
academic session
search
status
class
fee name
fee type

and then apply the selection scope.

---

IMPORTANT SECURITY REQUIREMENT

Never trust IDs coming from the browser.

If selected IDs are sent to the backend, the SQL query must still verify that every record:

- belongs to the current school/tenant
- belongs to the requested academic session
- satisfies the active filters
- is actually a valid fee_record

A user must never be able to manipulate an invoice ID and export another school's data.

---

IMPORTANT PERFORMANCE REQUIREMENT

This application uses server-side pagination.

The Ledger PDF must remain scalable.

Do NOT do this:

fetch page 1
fetch page 2
fetch page 3
...
fetch every page
combine everything in browser
generate PDF

Do NOT materialize thousands of records into React state.

Instead:

Browser
