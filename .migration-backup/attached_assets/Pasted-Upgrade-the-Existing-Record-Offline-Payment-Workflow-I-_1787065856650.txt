1. IMPORTANT — Multi-Tenant School Isolation

This is a multi-tenant school application.

Every payment operation must be strictly isolated by:

"school_id"

An admin from School A must NEVER be able to search, view, select, verify, or record a payment against an invoice, student, or payment belonging to School B.

Tenant isolation MUST be enforced server-side at the:

- Database level
- Query level
- API/backend level
- Authorization level

Do NOT rely only on frontend filtering or hidden UI elements.

For every relevant query, use the authenticated user's current "school_id".

Never perform something equivalent to:

WHERE invoice_number = ?

without tenant restriction.

It must effectively enforce:

WHERE school_id = authenticatedSchoolId
AND invoice_number = ?

The same principle applies to:

- Student lookup
- DSID lookup
- Invoice lookup
- Payment creation
- Payment history
- Receipt generation
- Invoice status updates
- Audit records

Even if an administrator manually knows another school's:

- Invoice Number
- Student ID
- DSID
- Payment ID

the backend must return no accessible record.

3. Invoice Verification Before Recording Payment

Before recording any manual payment, the backend must independently verify the selected invoice.

The backend must confirm:

1. Invoice exists.
2. Invoice belongs to the authenticated admin's "school_id".
3. Student belongs to the same "school_id".
4. Invoice belongs to that student.
5. Invoice belongs to the selected academic session where applicable.
6. Invoice is still payable.
7. Invoice has not already been completely paid.
8. There is no conflicting payment currently being processed.
9. The payment amount does not exceed the actual outstanding amount.
10. The invoice being paid is exactly the invoice selected by the administrator.

Never trust invoice/student/payment information supplied only by the frontend.

The database must be the final authority.
