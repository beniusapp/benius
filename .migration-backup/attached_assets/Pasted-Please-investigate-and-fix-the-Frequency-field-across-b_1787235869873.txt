Please investigate and fix the Frequency field across both places where an invoice is displayed:

1. Student Portal → Fees & Payments → Outstanding invoice cards
2. Invoice PDF / Invoice document

There is currently an inconsistency where Frequency is available for some invoices but missing for others.

Current Student Portal issue

In the Outstanding section, some invoices show Frequency correctly:

- INV-0091 → Frequency: One-Time
- INV-0090 → Frequency: One-Time

But other invoices do not show Frequency:

- INV-0078 → Monthly fee → Frequency missing
- INV-0072 → Equipment onetime → Frequency missing
- INV-0084 → Quarterly fee → Frequency missing

Current Invoice PDF issue

The same problem exists in the invoice itself.

For example, INV-0084 is a Quarterly fee, but in the Invoice Details table the Frequency column currently displays "—" instead of "Quarterly".

The invoice PDF clearly has a dedicated FREQUENCY column, so the correct frequency should be displayed there whenever the invoice has a frequency value.

---

IMPORTANT: AUDIT THE ROOT CAUSE FIRST

Before making changes, trace the complete data flow.

Check:

1. Fee structure/configuration
2. Invoice generation
3. "fee_records"
4. "/api/student/fees"
5. Student Portal Outstanding card
6. Invoice PDF renderer/data mapping

For the affected invoices, determine:

- What is stored in "fee_records.frequency"?
- What frequency is configured in the original fee structure?
- Is frequency being copied into the invoice when the invoice is generated?
- Does "/api/student/fees" return the frequency?
- Does the invoice API/data source return the frequency?
- Is the frontend receiving the value but failing to render it?
- Is the PDF renderer receiving the value but displaying "—"?
- At exactly which stage is the frequency being lost?

Do not simply add a UI fallback or derive Frequency from the Fee Name.

For example:

- Monthly fee → Monthly
- Quarterly fee → Quarterly
- Annual/yearly fee → Annual/Yearly
- One-time fee → One-Time

The value must come from the actual configured/invoice data, not from guessing based on the name.
