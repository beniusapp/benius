PURPOSE OF FIX 10
==================================================

We need to determine whether Academic Session is consistently enforced across ALL ACTIVE Examination-related data and calculation paths.

Fix 2 established strict session isolation for the main Teacher Examination score path.

Now we need to investigate whether secondary/legacy paths can still:

- retrieve scores from multiple Academic Sessions
- calculate averages using multiple Academic Sessions
- display historical data from multiple sessions when one session is selected
- combine current and archived results
- calculate promotion using the wrong session
- retrieve reports from the wrong session
- retrieve analytics from multiple sessions
- use active/current session when another session was selected
- omit session filtering
- silently treat sessionId as optional
- substitute NULL-session records
- use current student placement for historical session results
- use policies without understanding which Academic Session they belong to

The key question is:

> WHEN A USER IS VIEWING OR CALCULATING RESULTS FOR A SPECIFIC ACADEMIC SESSION, DOES EVERY RELEVANT EXAMINATION DATA PATH USE ONLY THAT EXACT SESSION?

Do not assume the answer.

Trace the actual code.

19. DO NOT CONFUSE ALL-TIME HISTORY WITH A BUG
==================================================

Some student timelines or dashboards may intentionally show a student's complete academic history across multiple years.

That is not automatically a violation.

The key distinction is:

If the UI says:

"Academic Session: 2028–2029"

then Examination results associated with that view should be 2028–2029 only.

If the UI explicitly says:

"Student History"
or
"All Academic Years"

then multi-session data may be intentional.

Document the distinction.
