Step 3A was correctly BLOCKED.

The blocking defect is genuine:

The application uses PostgreSQL-backed express-session through connect-pg-simple.

Each request can load an independent copy of the session. A normal:

req.session mutation
+
session.save()

does NOT provide compare-and-swap semantics.

Therefore an older request can:

1. load recovery state A
2. a newer request writes recovery state B
3. older request checks its stale in-memory A
4. older request clears A
5. older request saves the entire stale session
6. B is overwritten

A normal req.session.reload() does not solve this race.

We therefore need a minimal atomic PostgreSQL-backed session-store primitive.
