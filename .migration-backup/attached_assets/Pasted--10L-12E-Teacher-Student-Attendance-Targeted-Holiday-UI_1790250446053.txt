# 10L-12E — Teacher Student-Attendance Targeted-Holiday UI Alignment

Implement **ONLY 10L-12E**.

## Objective

Fix the Teacher → Student Attendance marking UI so that it does not incorrectly disable Attendance marking because of a targeted holiday belonging to another class/section.

The existing server-side write rule is authoritative:

> **Only an `All_School` holiday locks Teacher Student-Attendance marking.**

Targeted class/section holidays do NOT currently lock the Teacher Student-Attendance write API.

Therefore the UI must not impose a stricter rule than the server.

## Required behavior

### All_School holiday

If the selected Attendance date has an `All_School` holiday:

```text
Teacher marking = BLOCKED
```

Preserve the existing behavior.

### Targeted holiday for another class/section

Example:

```text
Holiday = Class 5-A
Teacher is marking = Class 5-B
```

The UI must NOT disable Attendance marking because of this holiday.

```text
Teacher marking = ALLOWED
```

### Targeted holiday for the current class/section

Do not invent a new business rule.

The existing server write contract says targeted holidays do not themselves lock the Attendance write.

Therefore the UI should not block the write solely because the selected class/section has a targeted holiday.

```text
Teacher marking = ALLOWED
```

The existing server-side authorization and all other existing Attendance restrictions remain authoritative.
