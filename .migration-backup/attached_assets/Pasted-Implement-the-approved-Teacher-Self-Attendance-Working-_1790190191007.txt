Implement the approved **Teacher Self-Attendance Working Days + Canonical Rate** change.

## 1. APPROVED BUSINESS RULE

Each school has its own configurable working weekdays.

Default:

* Monday = ON
* Tuesday = ON
* Wednesday = ON
* Thursday = ON
* Friday = ON
* Saturday = OFF
* Sunday = OFF

Admin can turn Saturday and/or Sunday ON.

At least ONE weekday must remain ON.

This setting is SCHOOL-WIDE for simplicity and is isolated by authenticated `schoolId`.

## 2. WORKING-DAY BEHAVIOR

If a weekday is OFF:

* Teacher attendance is not expected.
* The date is excluded from the Teacher Self-Attendance rate.
* Do not generate an Absent record.

If a weekday is ON:

* Teacher attendance is expected.
* Existing Teacher Attendance Policy determines the stored status.
* Do NOT create a new Saturday/Sunday-specific status.
* Existing statuses remain unchanged.

Therefore, if Saturday is enabled, the existing Attendance Policy applies to Saturday exactly like any other configured working day.

## 3. HOLIDAY RULE

Reuse the existing school holiday calendar.

For Teacher Self-Attendance rate:

* An `All_School` holiday overrides the working-day setting.
* That date is excluded from the denominator.
* No attendance entry is required.

Do NOT redesign the existing calendar system.

Targeted/class-specific holidays do NOT affect the general Teacher Self-Attendance rate in this implementation.

## 4. MISSING ATTENDANCE

For an applicable working day:

If there is no Teacher Self-Attendance record for that teacher/date, treat it as:

Absent = 0%

Do NOT create a synthetic database attendance row.

This is calculation-only behavior.

## 5. RATE FORMULA

Use one canonical server-side Teacher Self-Attendance rate calculator.

Status weights:

* Present = 1.0
* Late = 1.0
* Half Day = 0.5
* Absent = 0.0
* Leave = 0.0

Rate:

earned attendance weight / applicable working days × 100

Round to ONE decimal place.

If there are zero applicable working days, return 0.0%.

## 6. RATE PERIOD

For the selected Academic Session:

Start:

* Session start date

End:

* Earlier of:

  * today's date in IST
  * Academic Session end date

Future dates must never be counted.

All generated/calculated dates must remain strictly inside the selected Academic Session.

## 7. SESSION AND TENANT SECURITY

This is mandatory.

Every Teacher Self-Attendance rate/read must be scoped by:

* authenticated `schoolId`
* authenticated Teacher identity
* validated selected Academic Session ID

Never allow cross-school or cross-session attendance calculation.

Do not trust a client-supplied school ID.

Derive the school from the authenticated session and validate the selected Academic Session belongs to that school.

## 8. STORAGE

Use the existing `school_metadata` table for the school-wide working-day configuration.

Do NOT create a new database table.

Store one validated JSON value for the school's weekday configuration.

Example conceptual shape:

{
"monday": true,
"tuesday": true,
"wednesday": true,
"thursday": true,
"friday": true,
"saturday": false,
"sunday": false
}

Requirements:

* exactly the seven valid weekday identifiers
* boolean values only
* no duplicates/unknown weekday keys
* at least one day must be ON
* malformed configuration must NOT silently become "all days OFF"
* missing configuration must safely use the default Mon-Fri ON / Sat-Sun OFF

The new read/write path must derive `schoolId` from the authenticated Admin session.

## 11. CANONICAL RATE CALCULATOR

Create/use one shared server-side calculation path for Teacher Self-Attendance.

It must:

1. Validate authenticated school + teacher + selected Academic Session.
2. Determine Session start/end.
3. Determine today's date using IST.
4. Generate applicable calendar dates only within:
   Session start → min(today IST, Session end)
5. Apply school Working Days configuration.
6. Apply `All_School` holidays.
7. For each applicable working date:

   * use the teacher's stored attendance status if present
   * if no record exists, treat it as Absent for calculation
8. Apply the approved status weights.
9. Return the canonical rate rounded to one decimal.

Do not create synthetic attendance rows.

Use existing IST/date helpers such as `todayInIST`, `calendarWeekday`, and `addCalendarDays` where already available.

Do not use UTC date conversion for business-date calculations.
