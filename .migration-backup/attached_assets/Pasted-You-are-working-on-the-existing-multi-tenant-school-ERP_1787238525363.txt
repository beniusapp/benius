You are working on the existing multi-tenant school ERP application.

I want to make one focused change to the Admin Portal:

Admin Portal → Fees & Payments → Record Offline Payment

OBJECTIVE

Currently, when an admin searches for a student, multiple unpaid invoices can appear and the UI allows selecting multiple invoices together for one offline payment.

I do NOT want bulk/multi-invoice offline payments.

Change the workflow so that:

«ONE offline payment transaction must apply to ONE invoice only.»

The admin must record each unpaid invoice separately.

When the admin searches for a student:

1. Show all eligible unpaid/outstanding invoices for that student.
2. Keep the existing invoice information visible:
   - Fee Name
   - Invoice Number
   - Academic Session
   - Due Date
   - Amount
   - Existing relevant status information
3. The admin must be able to select only one invoice at a time.
4. Remove/disable multi-selection behavior.
5. Do NOT show a "2 invoices selected", "3 invoices selected", combined total, or any bulk-payment summary.
6. The payment-details step must always correspond to exactly one selected invoice.
7. The admin records the offline payment for that single invoice.
8. After successful recording, the invoice becomes paid according to the existing system behavior.
9. If the student has another unpaid invoice, the admin can record another offline payment separately by selecting that invoice and completing another transaction.

IMPORTANT ACCOUNTING RULE

Enforce this rule at the backend/API level as well as the frontend:

One offline payment record → exactly one fee/invoice record.

Do not rely only on disabling the checkbox UI.

The server must reject any request attempting to submit multiple invoice/fee IDs for a single offline payment transaction.

RECEIPT / NUMBERING

Preserve the existing invoice and receipt architecture completely.

For each offline payment:

- The existing permanent "invoice_number" must remain unchanged.
- Generate/store the appropriate receipt number using the existing receipt-number logic.
- One receipt must correspond to the one invoice that was paid.
- Do not overwrite the invoice number with the receipt number.
- Preserve all existing payment-history/audit records.

- Razorpay integration
- Online payment flow
- Razorpay orders

- Payment attempts

Preserve the current design and styling.

Simply change the selection behavior from:

Multiple invoices → one payment

to:

One invoice → one payment
