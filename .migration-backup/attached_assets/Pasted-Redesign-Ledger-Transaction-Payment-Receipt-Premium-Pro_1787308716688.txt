Redesign Ledger & Transaction Payment Receipt — Premium Professional Receipt

I want to completely redesign the payment receipt/document generated from:

Admin Portal → Fees / Ledger → Transaction Details → Receipt / Download PDF

I have reviewed the current receipt and it is too simple and looks like a basic generated document. The attached screenshots show the current design.

The new receipt must look like a premium, modern, professional school ERP financial receipt suitable for giving to parents, students, auditors, and school administration.

Do NOT just change colors or fonts. Redesign the information hierarchy, spacing, sections, typography, alignment, and visual structure while preserving all existing financial data and forensic accuracy.

---

1. Most important rule — DO NOT CHANGE FINANCIAL DATA

This is a UI/document redesign.

Do not change:

- invoice number
- receipt number
- payment amount
- payment date/time
- payment ID
- order ID
- authorization information
- student information
- fee information
- payment status
- payment method
- transaction identifiers
- existing receipt numbering logic
- invoice/payment relationships
- academic session
- database values

Do not create fake values.

Use the actual data already available from the transaction.

The receipt should feel similar to a professionally designed:

- modern school fee receipt
- banking transaction receipt
- premium SaaS financial document
- professional accounting document

It should NOT look like:

- a plain HTML table
- an old-fashioned government form
- a basic browser print page

- clean typography
- excellent whitespace
- strong visual hierarchy
- subtle borders
- subtle section backgrounds

- clear status badge
- professional alignment
- strong amount presentation
- consistent spacing
- school branding
- modern but restrained design

The document must remain professional and printable.

3. Page format

Use a professional A4 portrait document by default.

The receipt should print cleanly on:

- A4
- standard office printers
- PDF
- browser print
- mobile "Save as PDF"

Avoid relying on Letter size.

The content must fit naturally within one page for normal transactions.

If a transaction contains unusually large amounts of metadata, allow a second page rather than shrinking the text to an unreadable size.

14. Timestamp requirement — VERY IMPORTANT

All school-facing dates and times must be displayed in:

Asia/Kolkata (IST)

Example:

20 Aug 2026, 08:22:41 PM IST

Do not use browser-local timezone.

Do not use device timezone.

Do not manually add "+05:30".

Use the centralized IST formatting utilities already established in the project.

Provider timestamps and application timestamps must remain separate facts.

For example:

Payment captured:
20 Aug 2026, 08:22:41 PM IST

Application recorded:
20 Aug 2026, 08:22:43 PM IST

Do not merge them if the system has both.
