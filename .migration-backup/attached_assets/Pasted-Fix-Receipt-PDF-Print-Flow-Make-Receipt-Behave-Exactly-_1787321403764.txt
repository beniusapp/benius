1. Existing Working Invoice Flow — DO NOT CHANGE IT

Frontend:

"client/src/pages/admin-modules/fees-manager.tsx"

Function:

"printInvoiceFromRecord"

Current logic:

const printInvoiceFromRecord = useCallback((recordId: number) => {
  const printWindow = window.open(`/api/admin/fees/${recordId}/invoice`, "_blank");
  if (!printWindow) {
    toast({ title: "Invoice could not open", ... });
  }
}, [toast]);

Backend route:

"GET /api/admin/fees/:id/invoice"

File:

"server/fees-routes.ts"

The route generates the invoice HTML through:

"server/invoice-document.ts"

"renderInvoiceDocument(data)"

The renderer returns a complete HTML document containing print CSS and:

<script>window.print()</script>

Therefore the flow is:

Click Invoice → open invoice HTML in new tab → browser automatically opens Print dialog → user selects Save as PDF.

This is the behavior I want for Receipt.

2. Current Receipt Flow

Receipt currently opens:

/api/admin/fees/payments/${offlinePayment.id}/receipt

or:

/api/admin/fees/${rec.id}/receipt

These routes already generate the receipt HTML through:

"server/receipt-renderer.ts"

The receipt renderer already contains the required print logic:

if (window.location.search.indexOf('print=1') !== -1) {
  window.onload = function() {
    window.print();
  };
}

Therefore the receipt system is already capable of doing exactly what the invoice does.

The problem is simply that the Receipt URL is currently opened without "?print=1".

Change the Receipt button URLs so they include:

"?print=1"

Change:

/api/admin/fees/payments/${offlinePayment.id}/receipt

/api/admin/fees/payments/${offlinePayment.id}/receipt?print=1

And change:

/api/admin/fees/${rec.id}/receipt

/api/admin/fees/${rec.id}/receipt?print=1
