# 1. CONTEXT

Step 2L-4 addressed this problem:

Previously:

```text
Student physically deleted
        ↓
attendance_records.student_id
        ↓
ON DELETE CASCADE
        ↓
historical Attendance deleted ❌
```

The implemented design claims to provide:

```text
Student physically deleted
        ↓
students row deleted
        ↓
attendance_records preserved
        ↓
student_id becomes NULL
        ↓
historical identity snapshot remains
        ↓
historical Attendance remains accessible
```

The implementation reportedly introduced:

* historical `identity_key`;
* historical Student name snapshot;
* historical digital-ID snapshot;
* nullable `student_id`;
* `ON DELETE SET NULL`;
* revised Attendance uniqueness;
* triggers protecting historical identity;
* migration/backfill logic.

We need to verify that this is actually safe and correct.
