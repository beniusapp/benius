==================================================
OBJECTIVE
==================================================

Determine the existing, intended definition of a WRITABLE Academic Session in this application.

Do NOT invent a new definition.

Trace the actual Academic Session model, session-view behavior, archive behavior, and Attendance mutation routes.

We specifically need to establish:

1. What field/state identifies the currently writable Academic Session?
2. How does the application distinguish:
   - active/current Session
   - archived/previous Session
   - future Session, if supported
3. Whether Session start/end dates affect writability.
4. Whether Attendance mutation currently has a seven-day edit rule.
5. Whether that seven-day rule is intended to remain for the current Session.
6. Whether an archived Session should ALWAYS be read-only even when its end date is within seven days.
7. Whether a current/writable Session can legitimately contain dates outside its nominal start/end range.
8. Whether Student Attendance and Teacher self-attendance should use exactly the same Session writability rule.
9. Whether there is already a shared helper that should be reused.
10. Whether any existing route has a different legitimate rule that must be preserved.
