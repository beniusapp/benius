## ATTENDANCE FIX #1 — LEGACY DAILY SUMMARY TENANT ISOLATION

We have completed a read-only Attendance audit.

Fix **ONLY this confirmed defect**:

### Defect

Route:

`GET /api/attendance/daily-summary/:schoolId/:date`

Current problem:

* It checks that the user is logged in.
* It accepts `schoolId` from the URL.
* It does NOT verify that:

`req.session.schoolId === req.params.schoolId`

* It also does not enforce the appropriate Admin authorization.
* Therefore a user from School A could potentially request a daily summary for School B.

This is a **multi-tenant isolation defect**.

---

## REQUIRED FIX

Before executing the daily-summary query:

### 1. Require authenticated school context

Use the authenticated session school:

`req.session.schoolId`

Do NOT trust the URL `schoolId` by itself.

### 2. Require same-school access

The requested URL school ID must equal the authenticated session school ID.

Conceptually:

```text
requestedSchoolId === authenticatedSchoolId
```

If not, reject the request.

Use the project's existing authorization/error-response convention. Do not invent a new authentication system.

### 3. Preserve existing role/security behavior

Inspect the current route and determine the intended authorized role(s).

The route is an Admin Attendance summary endpoint, so ensure unauthorized roles cannot use it.

Do not weaken any existing authentication or authorization.

### 4. Preserve existing data filtering

The database query must continue to use:

```text
school_id = authenticated school
AND
session_id = validated session
```

Do not remove any existing school/session filters.
