Add PDF Download for Ledger & Transaction History

I have verified the Student Portal. The Invoice and Payment Receipt already work correctly: they can be opened in Chrome and downloaded/saved as PDF using the browser's PDF functionality.

Now I need you to implement the same professional PDF capability for the Admin Portal → Fees & Payments, specifically:

1. Ledger — PDF Download

Add a clear "Download PDF" action to the Ledger section.

The PDF must be generated from the actual ledger data, not by taking a screenshot or simply printing the webpage UI.

The generated PDF should include:

- School logo and school information
- School name
- Academic Session
- Report title: Fee Ledger
- Applied filters
- Student name / Student ID where applicable
- Invoice Number
- Receipt Number
- Fee Name / Fee Type
- Fee Period
- Payment Date
- Payment Mode
- Amount
- Payment Status
- Any other important ledger information already available in the ledger

The PDF must reflect the currently selected filters. If the user filters by academic session, date, student, payment mode, status, etc., the downloaded PDF must contain only the filtered records.

2. Transaction History — PDF Download

Add a clear "Download PDF" action to the Transaction History section.

Again, generate the PDF from the actual transaction/payment data, not a screenshot of the page.

Include appropriate transaction information such as:

- School information and logo
- Academic Session
- Report title: Payment Transaction Report
- Applied filters
- Student Name / Student ID
- Invoice Number
- Receipt Number
- Payment Date & Time
- Payment Mode
- Amount
- Payment Status
- Payment ID / Order ID for online payments where applicable
- Transaction/reference number where applicable
- Any other important transaction information already displayed in the transaction history

The existing:

- Student Portal Invoice PDF
- Student Portal Payment Receipt PDF
- Admin Receipt rendering

4. PDF Quality

The PDF must be a proper professional document suitable for school accounting records.

Requirements:

- Clean A4 layout
- Proper margins
- School branding
- Clear table headers
- Readable font sizes
- Proper column widths
- Automatic pagination for large datasets
- Repeat table headers on every page
- Page numbers
- Report generation date/time in IST
- No content should be cut off
- No overlapping columns/text
- Amounts must be formatted correctly in INR
- Maintain consistent styling with the existing invoice/receipt design

5. Large Data Sets

Do not generate the PDF only from the records currently rendered on screen if the ledger/transaction table uses pagination or lazy loading.

The PDF must contain all records matching the currently selected filters, even if those records are spread across multiple pages in the UI.

Do not silently truncate the report.

If there are no matching records, show a clear message such as:

"No records found for the selected filters."

and do not generate an empty/broken PDF.

6. Security & Data Accuracy

Use the same authorization and tenant isolation already used by the Fees & Payments module.

A user must only be able to export data belonging to their authorized school/tenant.

Do not expose data from another school.

The PDF must use the same authoritative database values used by the ledger/transaction screens. Do not recalculate or invent financial values.

7. Download Behaviour

When the user clicks:

Download PDF

the application should generate and download the PDF directly.

Use meaningful filenames, for example:

- "Fee-Ledger-2027-2028.pdf"
- "Payment-Transaction-Report-2027-2028.pdf"

If filters are applied, the filename may include a useful filter/date identifier.
