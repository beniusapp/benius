FIX 10A — STUDENT EXAMINATION ACADEMIC SESSION ISOLATION
IMPLEMENTATION — NARROW SCOPE ONLY

We are building a TRUE MULTI-TENANT SaaS School MIS intended for 1,000+ independent schools.

Each school is an independent tenant.

NON-NEGOTIABLE TENANT RULE:
A user/student from School A must NEVER be able to access, retrieve, calculate with, save, update, modify, or infer School B's:
- students
- examination scores
- academic sessions
- policies
- results
- attendance
- faculty
- reports
- analytics
- or any other school-owned data.

The authenticated user's school/tenant context is authoritative.

Any client-supplied schoolId must NEVER be trusted for authorization.

==================================================
FIX 10A PURPOSE
==================================================

Implement ONLY the Student Examination Academic Session isolation fixes identified by the Fix 10 investigation.

The confirmed primary defect is:

Student Results has a selected Academic Session in the UI, but the main Student Examination "all scores" request does not transport the selected session to the server.

As a result, the server can receive no session context and the score query can return scores from multiple Academic Sessions, including legacy NULL-session records.

The Student result calculator then operates on that mixed-session data.

There is also a confirmed Student rank issue:

Student class rank does not consistently receive/apply the selected Academic Session.

Fix these problems now.

1. Student Examination selected-session transport.
2. Student Examination server-side session validation.
3. Student Examination exact-session score retrieval.
4. Student Examination result calculation receiving only selected-session scores.
5. Student rank session scoping.
6. Student Examination print/result output inheriting correctly scoped data.
7. Tests proving the above behavior.

DO NOT IMPLEMENT ANYTHING ELSE.

==================================================

The important existing concepts include:

- authenticated user's school is authoritative
- selected Academic Session is transported using:
  x-view-session-id
- server request context can contain:
  req.viewSessionId
- strict session validation exists for Teacher Examination
- selected session must belong to authenticated user's school

However:

Do not assume the Teacher-specific resolver can be directly reused for Student routes.

The Student route must derive the authenticated student's school/tenant from the authenticated student identity and validate the selected Academic Session against that school.

==================================================

==================================================
STEP 3 — SERVER-SIDE STUDENT SESSION VALIDATION
==================================================

Inspect the Student Examination score route(s).

Identify the authenticated student from the server-side authenticated session.

Derive:

authenticatedStudentId
authenticatedSchoolId

Do NOT derive schoolId from the request URL or request body for authorization.

If the selected Academic Session is supplied:

1. Parse/validate the session ID.
2. Verify that the Academic Session exists.
3. Verify that the Academic Session belongs to authenticatedSchoolId.
4. Use the validated session ID for all Student Examination score retrieval in this path.
5. Reject a foreign-school session.

Use a safe generic error response.

Do not reveal whether another school's session exists.

Do NOT fall back to the active session if the user explicitly supplied a different selected session.

==================================================
STEP 4 — MISSING SESSION BEHAVIOR
==================================================

We need to preserve existing application behavior where appropriate, but Student Examination must not silently become cross-session when a selected session is required.

Determine from the current Student Examination UI whether a selected Academic Session is always expected.

If Student Examination always has a selected session:

- missing session must fail closed with a generic client-safe error.

If there is a legitimate current-session-only mode:

- use the existing application convention,
- but it must resolve the session against the authenticated student's school,
- and it must NEVER become an unscoped "all sessions" query.

IMPORTANT:

Do not silently interpret:

missing session = all sessions

inside a selected-session Student Examination result request.

If the existing contract is ambiguous, inspect the UI flow and current session context before deciding.

Do not invent business behavior.

STEP 5 — EXACT SCORE FILTER
==================================================

Once the session is validated, the Student Examination score query must use an exact session predicate.

Conceptually:

school_id = authenticatedStudentSchoolId
AND student_id = authenticatedStudentId
AND session_id = validatedSelectedSessionId

Do NOT use:

- no session filter
- active session fallback when an explicit session exists
- NULL-session fallback
- all-session query
- client schoolId as authorization
- current academic year string as a substitute if an exact session ID is available

If the existing storage function accepts optional sessionId, pass the validated session explicitly.

Do not change global storage semantics unless required for this Student Examination path.
