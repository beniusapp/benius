==================================================
MY EXACT ATTENDANCE REQUIREMENTS
==================================================

1. SESSION-SPECIFIC ATTENDANCE

The entire Attendance module must be Academic Session-specific:

- Teacher Attendance
- Student Attendance
- Admin Attendance

Every Attendance record must be linked to an Academic Session ID.

Attendance data must belong to exactly one Academic Session.

If I switch to another Academic Session:

- I must see only Attendance belonging to that Session.
- I must not see Attendance from another Session.

Example:

Session 2021–2022
    Attendance A

Session 2025–2026
    Attendance B

When 2021–2022 is selected:

    show Attendance A only.

When 2025–2026 is selected:

    show Attendance B only.

==================================================
2. STUDENT REGISTRY IS GLOBAL
==================================================

The Admin Student Registry is GLOBAL/PERMANENT.

Student Registry data must NOT be recreated or reset when:

- a new Academic Session is created
- an Academic Session ends
- the active Academic Session changes
- an old Academic Session is selected

The Student Registry is the permanent Student Master.

Teacher Attendance should simply:

    fetch students from Student Registry
            ↓
    mark Attendance for those students

DO NOT make session Enrollment a new prerequisite merely because an
Enrollment table exists.

DO NOT assume students must be recreated for every Academic Session.

==================================================
3. TENANT-SPECIFIC
==================================================

Attendance must be strictly tenant/school-specific.

A Teacher from School A must never:

- see School B Attendance
- create School B Attendance
- modify School B Attendance

A Student from School A must never see School B Attendance.

An Admin from School A must never see School B Attendance.

Authenticated school/tenant context must be authoritative.

Browser-supplied school IDs must never be trusted as ownership authority.

==================================================
4. ANY TEACHER CAN MARK ATTENDANCE
==================================================

Any authenticated Teacher belonging to the same school can mark
Attendance.

Do NOT introduce Faculty Mapping restrictions.

Do NOT introduce class-assignment restrictions.

Do NOT introduce subject-assignment restrictions.

Do NOT add additional Teacher eligibility rules unless they already
exist as a required security check.

==================================================
5. HISTORICAL ATTENDANCE MUST REMAIN VISIBLE
==================================================

Historical Attendance must remain available when its Academic Session
is selected.

Example:

Academic Session: 2021–2022

Class 6A:
    8 students

Class 7A:
    90 students

Attendance is recorded.

Later:

Academic Session: 2025–2026

The Student Registry may now be different.

For example:

RAM JAISWAL existed in the school during 2021–2022.

Later, Ram Jaiswal is no longer present in the current Student Registry.

When I select:

    Academic Session 2021–2022

the system MUST still display Ram Jaiswal's historical Attendance.

The historical Attendance record must not disappear simply because the
Student is no longer present in the CURRENT Student Registry.

Therefore, audit whether historical Attendance currently depends on
the current Student Registry for display.

DO NOT fix this yet.

Only report the current behavior.
