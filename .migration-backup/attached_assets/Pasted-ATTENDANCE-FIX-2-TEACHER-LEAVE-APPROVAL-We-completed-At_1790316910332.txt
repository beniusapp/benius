ATTENDANCE FIX #2 — TEACHER LEAVE APPROVAL

We completed Attendance Fix #1 successfully.

Now fix ONLY the second confirmed Attendance defect.

Problem

Route:

"PATCH /api/leave/:id/status"

When a Teacher Leave request is approved, the route can create/update "teacher_self_attendance" for the Leave's Academic Session.

Current problem:

The route checks the Leave's school and session ownership, but it does not require that the Leave's Academic Session is currently active.

Therefore:

Archived Session
→ Teacher Leave approved
→ Teacher Self-Attendance can be created/updated

This violates the Attendance rule:

«Archived Academic Sessions are read-only.»

---

REQUIRED FIX

Before Teacher Leave approval creates or updates "teacher_self_attendance":

1. Identify the Leave's Academic Session.
2. Verify that the Session belongs to the authenticated school.
3. Verify that the Session is the currently active/writable Session.
4. If the Session is archived/inactive:

REJECT

Do not create or update "teacher_self_attendance".

Use the project's existing Session authorization/error conventions.

---

IMPORTANT

Do NOT change normal Teacher Leave behavior for the active Session.

For an active Session:

Teacher Leave approval
→ existing Attendance synchronization continues normally

For an archived Session:

Teacher Leave approval
→ Attendance write is blocked

Do not silently modify archived Attendance.
