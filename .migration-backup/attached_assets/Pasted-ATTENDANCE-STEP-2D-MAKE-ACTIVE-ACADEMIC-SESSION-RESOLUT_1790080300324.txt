ATTENDANCE STEP 2D — MAKE ACTIVE ACADEMIC SESSION RESOLUTION EXPLICIT

IMPORTANT PROJECT RULES:

This is ONE small implementation step.

The goal is ONLY to move Active Academic Session resolution from
inside storage.upsertAttendance() into the POST /api/attendance route.

DO NOT change any other Attendance logic.

The existing Replit application behavior must remain unchanged except
for the specific Session-resolution behavior described below.

==================================================
CURRENT BEHAVIOR
==================================================

Current flow:

POST /api/attendance
    ↓
authenticated Teacher
    ↓
storage.upsertAttendance()
    ↓
getActiveSession(rec.schoolId)
    ↓
Attendance write

The problem is that:

- Session resolution happens inside storage.
- It can happen once per Student.
- It can return undefined.
- Attendance can therefore be written with session_id = NULL.
- The route does not have an explicit Session ID available for the
  later enrollment resolver.

==================================================
TARGET BEHAVIOR FOR THIS STEP ONLY
==================================================

Change the flow to:

POST /api/attendance
    ↓
authenticate Teacher
    ↓
derive authoritative schoolId from Teacher
    ↓
resolve ONE active Academic Session for that school
    ↓
if no active Session exists → reject request
    ↓
pass explicit sessionId into every formatted Attendance record
    ↓
storage.upsertAttendance()
    ↓
storage uses the supplied sessionId

The browser MUST NOT choose the Session.

==================================================
IMPORTANT — NOTHING ELSE CHANGES
==================================================

DO NOT implement the enrollment resolver in Attendance yet.

DO NOT call:

    resolveEnrollmentForStudentSession()

in this step.

DO NOT change:

- Student validation

==================================================
PART 1 — ROUTE CHANGE
==================================================

Modify ONLY the POST /api/attendance route as necessary.

After:

    const teacher = await storage.getTeacherById(req.session.teacherId)

and after authoritative schoolId is known:

    const schoolId = teacher.schoolId

resolve the active Session ONCE:

    const activeSession = await storage.getActiveSession(schoolId)

Use the repository's existing types/conventions.

If no active Session exists:

- reject the request explicitly
- do not call storage.upsertAttendance()
- do not write any Attendance records

Use the existing project's appropriate HTTP status/error response
convention.

Do not invent a new response format unless required.

==================================================
PART 2 — PASS EXPLICIT SESSION ID
==================================================

When the route builds the formatted Attendance records, add:

    sessionId: activeSession.id

to every record.

The resulting record should retain all existing fields and behavior.

For example, conceptually:

{
    studentId,
    teacherId,
    schoolId,
    date,
    status,
    markedBy,
    class,
    section,
    academicYear,
    sessionId: activeSession.id
}

Do NOT remove or change any existing field in this step.

==================================================
PART 3 — STORAGE COMPATIBILITY
==================================================

Inspect:

    storage.upsertAttendance()

Current behavior:

    if sessionId exists
        use it
    otherwise
        getActiveSession()

For this step:

- The route must always provide sessionId.
- Existing storage support for an explicitly supplied sessionId may
  remain unchanged.
- DO NOT refactor unrelated storage logic.
- DO NOT remove the fallback yet unless you can prove that doing so
  does not affect any other existing caller.

IMPORTANT:

Before changing/removing the fallback, search the repository for ALL
callers of:

    upsertAttendance()

If other callers depend on the fallback, preserve compatibility.

The only required behavior for the Teacher Attendance route is that
its records now contain the explicit active Session ID.

==================================================
PART 4 — SESSION TENANT SAFETY
==================================================

The Session MUST be resolved using:

    teacher.schoolId

NOT:

- browser schoolId
- browser sessionId
- request body sessionId
- Student schoolId
- submitted class/section

The browser must not be allowed to select another Session.

If the request body already contains any unexpected sessionId field,
do not use it as authority.

The authoritative Session is always:

    storage.getActiveSession(teacher.schoolId)

==================================================
PART 5 — RESOLVE ONLY ONCE
==================================================

The active Session lookup must happen once per POST /api/attendance
request.

Do NOT resolve the active Session separately for every Student.

The resulting:

    activeSession.id

must be reused for every record in that batch.

==================================================

- IST today restriction
- seven-calendar-day restriction
- school-holiday restriction
- Teacher authentication
- authenticated-school derivation

These must continue working exactly as before.

The only new validation is:

    active Session must exist
