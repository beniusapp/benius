IMPORTANT:
This is a READ-ONLY investigation.
DO NOT modify any code, database, schema, migration, configuration, environment variable, dependency, or production/development data.

Our MIS is an Indian school-management application.

NON-NEGOTIABLE REQUIREMENT:
The entire application must use IST (Asia/Kolkata) as the application's business/user-facing timezone.

We must NOT have application-facing times represented or interpreted as BST, UTC, browser-local time, server-local time, or any other timezone.

Audit the ENTIRE codebase and determine exactly how timezone/date/time handling currently works.

Inspect:

- Date/DateTime handling

- database timestamp handling
- SQL CURRENT_TIMESTAMP / NOW()

- start-of-day/end-of-day logic
- scheduled/background jobs
- API-generated timestamps

Determine whether backend logic consistently uses Asia/Kolkata where business/user-facing time is required.
