==================================================
GOAL
==================================================

Change Attendance persistence so that the canonical identity is exactly:

    school_id + session_id + student_id + date

There must be exactly one attendance_records row for that combination.

A Student/date in one Academic Session MUST NOT update or overwrite the same Student/date in another Academic Session.

A Student/date in one school MUST NOT update or overwrite Attendance belonging to another school.

Every attendance_records row must have a non-null session_id.

File:

    server/storage.ts

Function:

    upsertAttendance()

Change existing-row detection from:

    studentId + date

to:

    schoolId + sessionId + studentId + date

Requirements:

    school_id

    date

==================================================

The database must enforce:

    UNIQUE (
        school_id,
        session_id,
        student_id,
        date
    )

Also make:

    attendance_records.session_id

NOT NULL.

Because session_id is now part of the canonical identity, the current:

    ON DELETE SET NULL

foreign key behavior is incompatible.

Change the Attendance -> Academic Session foreign key to a delete behavior that preserves Attendance history and never nulls session_id.

Preferred behavior:

    ON DELETE RESTRICT / NO ACTION

Use the project's existing migration/schema conventions if one is already established.
