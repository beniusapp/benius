## PHASE

The application is in the **BUILDING / DEVELOPMENT phase**.

The purpose is to determine the exact current Attendance working-day, Sunday, holiday, and leave semantics before deciding whether any implementation change is actually required.

---

# IMPORTANT PROJECT RULES

These are existing project requirements and MUST remain unchanged:

1. The application is **multi-tenant / multi-school**.
2. Attendance must always be isolated by authenticated **school/tenant**.
3. Student Registry is **GLOBAL/PERMANENT** and must not be recreated/reset per Academic Session.
4. Attendance is strongly **Academic Session-specific**.
5. Archived Academic Sessions are read-only.
6. The active Session retains the existing **7-day Attendance correction window**.
7. Sunday is NOT automatically a working day.
8. A Sunday MAY be deliberately marked for Attendance.
9. If a Sunday is deliberately marked, it uses the normal stored Attendance status semantics.
10. Application/business/display timestamps use **IST / Asia/Kolkata**.
11. Do not infer or invent product rules that the current application does not establish.

---

# CURRENT AUDIT CONTEXT

Previous Attendance audits identified a remaining ambiguity/inconsistency around **working-day semantics**.

Current implementation appears to have several different concepts:

* calendar weekdays
* Sundays
* school holidays
* dates with Attendance records
* approved leave
* class/Session Attendance evidence
* missing Attendance
* explicitly marked Attendance

The existing calculation code appears to use Attendance evidence in some places rather than simply treating every weekday as a working day.

We need to establish the exact current behavior before making any change.
