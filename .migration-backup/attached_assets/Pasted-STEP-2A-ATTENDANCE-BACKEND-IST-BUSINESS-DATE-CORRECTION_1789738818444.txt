3. FIX STUDENT CLASS-ATTENDANCE ACADEMIC-YEAR CALCULATION
==================================================

Current problematic pattern identified around:

server/teacher-routes.ts:438-442

The current logic approximately does:

const dateObj = new Date(date);
const yr = dateObj.getFullYear();
const mo = dateObj.getMonth();

This must no longer depend on the server timezone.

The submitted Attendance date is a calendar date:

YYYY-MM-DD

It must be interpreted as an Indian school calendar date.

Use the existing canonical IST/date-only utilities from:

shared/ist-time.ts

Prefer the existing helper if it directly supports this requirement, such as:

getAcademicYearForISTDate()

Do NOT create a duplicate timezone utility if an existing canonical helper can perform the calculation.

The resulting academic year must be based on the calendar date itself.

Examples:

2026-03-31
→ academic year 2025-26

2026-04-01
→ academic year 2026-27

These results must be identical regardless of the server/container timezone.

==================================================
4. VALIDATE ATTENDANCE DATE BEFORE ACADEMIC-YEAR CALCULATION
==================================================

The Step 2 audit also identified that the Attendance route does not strictly validate that the supplied date is a valid calendar date before using it.

If the current Attendance route accepts:

date = "YYYY-MM-DD"

then validate it as a real calendar date before performing academic-year logic.

Requirements:

- exactly YYYY-MM-DD format
- valid month
- valid day
- reject impossible dates such as:
  2026-02-30
  2026-13-01
  2026-00-10
- do not silently normalize invalid dates
- preserve valid dates exactly as YYYY-MM-DD

IMPORTANT:

Do not convert the validated calendar date into a timezone-bearing JavaScript Date merely to validate it.

Use date-only/calendar-safe validation.

Do not alter the database DATE column.

5. FIX TEACHER SELF-ATTENDANCE CORRECTION WINDOW
==================================================

Current problematic logic identified around:

server/teacher-routes.ts:4673-4674

The current logic approximately does:

const diffDays = Math.floor(
  (Date.now() - new Date(date + "T00:00:00").getTime()) / 86400000
);

This is NOT acceptable because:

new Date(date + "T00:00:00")

means midnight in the server/process timezone.

The Attendance correction window is an Indian school business rule.

It must be based on IST calendar dates.

Do NOT calculate the correction window by subtracting JavaScript timestamps from server-local midnight.

Instead:

1. Determine today's date using the canonical IST helper:

todayInIST()

2. Treat the submitted attendance date as a validated YYYY-MM-DD calendar date.

3. Calculate the calendar-day difference using date-only/calendar-safe arithmetic.

4. Apply the existing seven-day correction rule without changing its intended business meaning.

The calculation must be independent of server timezone.
