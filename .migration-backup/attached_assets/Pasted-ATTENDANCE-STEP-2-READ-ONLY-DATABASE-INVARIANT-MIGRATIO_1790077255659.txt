PROJECT HARD REQUIREMENTS:
1. This is a multi-tenant school MIS.
2. Every school is an isolated tenant.
3. No Student, Teacher, Enrollment, Attendance, Academic Session, or other school-owned record may cross school boundaries.
4. Authenticated school/tenant context is authoritative.
5. Browser-supplied schoolId must never establish ownership.
6. Academic Session is mandatory for session-scoped Student Attendance.
7. Application business/display dates use Asia/Kolkata / IST.
8. Do not introduce a global timezone configuration that changes existing Postgres timestamp semantics.
9. Existing unrelated modules must not be redesigned.
10. Student Registry remains the global/current Student master.
11. Enrollment remains the session-specific placement authority.
12. Historical Attendance must not move when current Student Registry or enrollment placement changes unless a separately audited correction operation is later designed.
13. Teacher Examination's existing authorization architecture must not be copied blindly into Attendance. Attendance's own business contract must remain explicit.
14. Do not solve unresolved product-policy questions by guessing.

KNOWN ATTENDANCE CONTRACT FROM STEP 1/1A:

STUDENT ATTENDANCE IDENTITY:

school_id + session_id + student_id + attendance_date

Canonical uniqueness should eventually be:

UNIQUE (
    school_id,
    session_id,
    student_id,
    attendance_date
)

SESSION:
- Attendance writes use the authenticated school's active Academic Session.
- Browser cannot choose the write session.
- Historical sessions are read-only.
- Attendance must retain its session identity.
- A referenced historical Academic Session must eventually be archived/deactivated rather than hard-deleted.

ENROLLMENT:
- Attendance requires a matching enrollment:
  school_id + student_id + session_id
- Enrollment is the session-specific authority for class and section.
- Attendance class/section should be historical snapshots derived from enrollment at mark time.
- Browser class/section must not be trusted as authority.
- Enrollment status vocabulary is NOT yet finalized, so do not invent a status allowlist in this step.

STUDENT:
- students has school ownership.
- Student identity must be tenant-bound.
- Current students.class / students.section must NOT be used to reconstruct historical Attendance placement.

TEACHER:
- Teacher identity is tenant-bound.
- Current Attendance behavior allows any authenticated same-school Teacher.
- Assignment restriction (Faculty Mapping vs legacy assignment vs unrestricted same-school Teacher) remains a product decision.
- Do not implement assignment restrictions in this step.

STATUS:
Settled future canonical persisted Student Attendance statuses:
- present
- absent
- late
- halfday

Do not persist:
- not-marked
- none
- holiday
- future

half_day is legacy compatibility only if real legacy data exists.

leave remains unresolved because leave authority/precedence/percentage rules are still a product decision.

EDIT COUNT:
Future intended contract:
- initial creation = edit_count 0
- only changed status increments edit_count
- unchanged save = no update/no increment
- maximum Teacher changes = 3
- cap failure must be explicit
- enforcement must be atomic
- seven-day Teacher edit window uses IST calendar arithmetic
- Admin override/correction behavior remains unresolved

TEACHER SELF ATTENDANCE:
Current logical identity:
school_id + teacher_id + attendance_date

It is a separate subsystem.
Do NOT redesign Student Attendance identity based on Teacher self-attendance.

- attendance_records currently has no unique constraint for Student/day.

- Current Attendance tables were apparently created outside tracked migrations / likely through previous Drizzle schema push.
- No tracked migration currently establishes the complete Attendance DDL.
