==================================================
GOAL
==================================================

Create a secure server-side recovery-session mechanism for Teacher Forgot Password.

The browser must NOT be trusted to carry:

- schoolId
- userId
- teacherId
- challengeId
- resetToken

between recovery stages.

The server-side recovery session must become the source of truth.

The intended future flow is:

Teacher Login
→ School Code + Email
→ server resolves school + Teacher
→ create recovery challenge
→ server stores recovery challenge identity in recovery session
→ OTP email
→ browser submits OTP
→ server reads challenge/user/school from recovery session
→ Step 4 verifies OTP
→ server stores newly generated reset token in recovery session
→ browser submits new password
→ server reads recovery identity/reset token from recovery session
→ Step 2 performs atomic password reset
→ recovery session destroyed

Step 5 implements ONLY the server-side recovery-state foundation.

==================================================
RECOVERY STAGES
==================================================

Support at least these states:

### OTP_PENDING

Created after successful Step 3 challenge creation.

Must contain:

- challengeId
- userId
- schoolId
- teacherId
- stage = OTP_PENDING
- creation timestamp

Must NOT contain the plaintext reset token yet.

### PASSWORD_RESET

Created after successful Step 4 OTP verification.

Must contain:

- challengeId
- userId
- schoolId
- teacherId
- stage = PASSWORD_RESET
- newly generated plaintext resetToken
- appropriate timestamp

The reset token exists only in trusted server-side session state.

Do NOT store the plaintext reset token in the database.

Do NOT send the reset token to the browser.

==================================================
SESSION CREATION
==================================================

Add a server-side helper conceptually equivalent to:

startTeacherPasswordRecoverySession(
  req,
  {
    challengeId,
    userId,
    schoolId,
    teacherId
  }
)

It must:

- create/replace Teacher recovery state
- bind the exact challenge/user/school/Teacher
- set stage = OTP_PENDING
- clear any previous Teacher resetToken
- establish a fresh recovery timestamp

Do not modify normal authentication state.

The Teacher is NOT logged in by this operation.

==================================================
AFTER OTP VERIFICATION
==================================================

Add a server-side helper conceptually equivalent to:

markTeacherPasswordRecoveryVerified(
  req,
  resetToken
)

It must:

1. Require an existing OTP_PENDING Teacher recovery state.
2. Preserve:
   - challengeId
   - userId
   - schoolId
   - teacherId
3. Change stage to PASSWORD_RESET.
4. Store the newly generated resetToken ONLY in server-side recovery session state.
5. Refresh the recovery timestamp.

The resetToken is the NEW token generated by Step 4.

Do NOT accept a reset token from the browser.
