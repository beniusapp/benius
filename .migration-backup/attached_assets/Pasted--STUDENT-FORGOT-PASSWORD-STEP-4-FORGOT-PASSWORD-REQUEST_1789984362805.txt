G. FORGOT PASSWORD REQUEST
==================================================

Create:

POST /api/student/forgot-password

Request body must contain only the actual required recovery identity fields, for example:

  schoolCode,
  [actual Student recovery identifier]
}

Do NOT accept:

- schoolId
- tenantId
- studentId
- email
- contactId
- challengeId
- resetToken

Extra fields must be ignored.

Do not allow the browser to choose the destination email.

Flow:

1. Validate request shape.
2. Normalize school code according to existing school-code conventions.
3. Resolve exact school.
4. Resolve exact active Student within that school.
5. Resolve the Student's current verified recovery contact.
6. Validate that the verified contact still matches the Student's current email.
7. Resolve that school's notification configuration.
8. Generate a cryptographically secure six-digit OTP.
9. HMAC/hash OTP using existing accepted crypto infrastructure.
10. Create the Step 2 password-reset challenge transactionally.
11. Start/update the Step 3 server-bound recovery session as OTP_PENDING.
12. Send OTP through the exact resolved school's configured provider.
13. Never expose OTP to browser.
14. Return the generic response.

IMPORTANT:

Do not create the challenge first and then blindly send to an arbitrary address.

The destination must be the server-resolved verified recovery contact.
